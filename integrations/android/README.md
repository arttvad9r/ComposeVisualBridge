# Сбор данных с Android Compose

Для показа оригинального Preview без HTML-реконструкции используйте [подключение Buddy](../../docs/native-ui.md). Описанный ниже capture-помощник — альтернативный сбор измерений для режима макета.

Помощник `ComposeBridgeCapture.kt` собирает настоящий снимок и измерения конкретного экрана. Это входные данные для подготовки макета, а не автоматический конвертер приложения в JSON редактора.

Скопируйте файл в `src/androidTest/java/dev/composevisualbridge/capture/` согласованной тестовой копии Android-проекта. Нужен существующий Compose instrumentation-тест с `ComposeContentTestRule` и зависимостью `ui-test-junit4`. После открытия экрана и установки нужного состояния вызовите:

```kotlin
import dev.composevisualbridge.capture.captureComposeScreen
import java.io.File

captureComposeScreen(
    rule = rule,
    folder = File(context.filesDir, "bridge"),
    name = "settings-light-ru",
    sourceRevision = "фактический хеш исходников",
    screenState = "SettingsScreen, тестовый аккаунт, ru, LIGHT",
)
```

`context` — контекст тестируемого приложения. Снимайте после загрузки данных, без открытых меню и анимаций. Имя должно быть уникальным: помощник отказывается заменять существующие PNG/JSON. Для debug-приложения результаты можно получить через `adb exec-out run-as <applicationId> cat files/bridge/settings-light-ru.json` и аналогично PNG. Внешние данные и аккаунт не требуются: используйте воспроизводимую тестовую сцену.

JSON содержит viewport в dp, density, fontScale, boundsDp, связи semantics, текст, роли, selected и доступную типографику TextLayoutResult в sp. Геометрия относится к области `onRoot`; используйте `viewport.presentation=content`. Семантические ID действуют только в данном запуске: стабильные ID редактора и ссылки source необходимо сопоставить с реальным кодом.

Размер шрифта, цвет, межстрочное расстояние и ограничение строк берите из экспорта. Не копируйте `maxLines=2147483647` в модель: отсутствие maxLines означает неограниченный текст. Неизвестные значения остаются неизвестными; inline-стили требуют отдельной проверки. Экспорт не содержит всей графики, обводок, скруглений, иконок и параметров контейнеров — они определяются по исходникам и сверяются со снимком. Совпадение bounds само по себе не подтверждает макет.

Для системного Roboto в проверенном Android API 36 пакет содержит AOSP Roboto 3.005. Для других устройств и пользовательских шрифтов метрики нужно сверить отдельно. Масштаб устройства храните в fontScale; исходные свойства текста сохраняйте в sp.

После подготовки отдельной сессии загрузите PNG командой `reference` и предложите пользователю сравнить исходник в редакторе. Агент не подтверждает baseline вместо пользователя. Запуск сбора не разрешает перенос визуальных правок в Android-код.
