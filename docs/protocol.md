# Модель данных и API

## Возможности переноса Compose

В новых Compose-снимках `changes.json` содержит дополнительное необязательное поле `transfer: {target: "android-compose", requiresAgent: [{id, property, reason}]}`. Оно вычисляется из baseline/proposed по общей матрице `public/compose-capabilities.mjs`, не изменяет intent и не даёт разрешения на запись в проект. Старые снимки без этого поля остаются читаемыми. Причины также включаются в report.md; в `/api/handoff` они доступны как transfer и через отчёт, также доступны в `/api/applied`, а baseline/document позволяют вычислить их заново.

CLI `compose-plan` возвращает `strategy=adapter` вместе с `plan`, либо `strategy=agent` с `requiresAgent`, `applied` и полным `document`. Второй путь не создаёт частичный Kotlin-план и не пишет исходники. Связанные с ресурсами/состоянием тексты, TextField/Switch/Icon/Image и Roboto Flex требуют разрешения агентом. Проверка baseline, актуальной ревизии и поручение на перенос сохраняются. Подчёркивание и вертикальная прокрутка имеют прямой перенос; stretch у Row/Column кодируется заполнением поперечной оси детей с естественным размером, без замены их числовых размеров.

Источником точных допустимых значений служит `public/model.mjs`. Протокол v1 используется и браузером, и агентом.

Compose-импорт 0.8.2 добавляет `compose.modifierModel="outer-size-v1"` и `compose.bindings[id].modifierLayout.order`: массив групп модификаторов в исходном порядке. Группы: width, height, padding, offset, background, opacity, radius, border, weight, clipContent, scrollable. Новые свойства дописываются в этом порядке после существующих групп. width/height в таком документе — внешние размеры в dp; адаптер вычитает padding, стоящий перед соответствующим размером в Kotlin. При изменении padding сохраняется числовой внешний размер. Порядок также определяет область background: после padding фон занимает внутреннюю область. Renderer и адаптер используют общую модель `public/modifier-layout.mjs`. Метаданные сохраняются вместе со снимком и не редактируются пользователем.

schemaVersion остаётся 1. Документы без modifierModel читаются по прежним правилам; изменённый старый Compose-импорт отклоняется автоматическим планировщиком с указанием повторного импорта в отдельную сессию. Старые черновики и снимки не переписываются. Повторяющиеся padding требуют отдельного адаптера; размер меньше внешних отступов и свободное преобразование контейнера с внутренним фоном отклоняются без частичного Kotlin-плана.

## Документ

```json
{
  "schemaVersion": 1,
  "name": "Настройки",
  "sourceRevision": "commit-and-source-snapshot",
  "state": {"theme": "light"},
  "viewport": {"width": 412, "height": 915},
  "root": {
    "id": "screen",
    "type": "Column",
    "props": {"width": "fill", "gap": 12},
    "children": [{
      "id": "title",
      "type": "Text",
      "props": {"text": "Настройки", "width": "fill", "textAlign": "center"},
      "source": {"file": "SettingsScreen.kt", "symbol": "SettingsScreen", "instance": "title"}
    }]
  }
}
```

Это пример структуры, а не проверенная ссылка на исходник. ID уникален в дереве. source описывает файл, символ, экземпляр; line и note необязательны. Числа размеров — dp, размер шрифта — sp. viewport: ширина 200–1500, высота 200–2000. Максимум 500 узлов и 30 уровней. Дополнительные метаданные документа допускаются, но неизвестные props отклоняются.

Типы: Column, Row, Box, Card, Text, Button, TextField, Switch, Icon, Image, Spacer. Только первые четыре содержат детей.

| Свойства | Значения |
|---|---|
| offsetX, offsetY | число от −4000 до 4000 dp; отсутствие равно 0; положительное X вправо, Y вниз |
| width, height | число 0–4000, auto, fill; отсутствие — по умолчанию |
| padding, paddingHorizontal, paddingVertical, gap | число 0–300 |
| align | start, center, end, stretch; положение листа или выравнивание детей контейнера |
| justify | start, center, end, space-between; распределение детей |
| textAlign | start, center, end, justify; строки внутри текстового блока |
| fontSize / lineHeight / fontWeight | 6–100 / 6–150 / 100–900 |
| fontStyle / textDecoration | normal, italic / none, underline |
| color, background, borderColor | HEX #RRGGBB |
| borderWidth / radius / weight / opacity | 0–10 / 0–200 / 0–100 / 0–1 |
| text, placeholder, label, supportingText, src | строки до 5000 символов; src — https или встроенный PNG |
| leadingIcon, trailingIcon | TextField: встроенный PNG иконки, вырезанный из кадра (только для показа) |
| checked, scrollable | boolean |

Ограничения валидатора не равны точному поведению Compose. Цвет/шрифт наследуются в веб-превью; сохранение темы и реальных модификаторов — задача агента.

## HTTP

| Метод | Путь | Поведение |
|---|---|---|
| GET | /api/session | revision, baseline, current, applied |
| PUT | /api/session | Архивировать прежнюю сессию; заменить baseline/current, очистить applied/reference/verification |
| POST | /api/session/restore | Архивировать текущую сессию и восстановить previousSession; revision увеличивается |
| POST | /api/baseline/reference | revision, image (base64), mime, label; сохранить эталон, снять подтверждение |
| POST | /api/baseline/confirm | revision, baselineFingerprint, acknowledged:true; явное подтверждение пользователем |
| GET | /api/reference | Изображение эталона текущей сессии |
| GET | /api/snapshots/applied-N-ID/reference | Изображение эталона неизменяемого снимка |
| PUT | /api/draft | Сохранить только current |
| POST | /api/apply | Сохранить current и отдельный снимок передачи |
| GET | /api/changes | Diff текущего черновика, draft:true |
| GET | /api/applied | Последний переданный diff; 404 до Apply |

Тело записи: `{"revision": актуальное_число, "document": документ}`; Content-Type: application/json. Успешная запись возвращает новую сессию и увеличивает revision на 1. PUT session заменяет baseline, поэтому не использовать его как сохранение черновика.

Коды: 400 — неверные данные; 403 — Host/Origin; 409 — устаревшая revision; 413 — больше 2 MB; 415 — неверный Content-Type. Проверка revision выполняется до записи. При 409 экспортируйте локальную работу, затем загрузите серверную версию; автоматического слияния нет.

## Снимок передачи

`data/session.json` хранит applied.directory. В этом каталоге находятся baseline.json, proposed.json и changes.json. GET applied возвращает changes.json, но для полного дерева агент также читает proposed.json из файловой системы.

Изменения: property — свойство, type — тип, children — окончательный порядок, reparent — родитель, add/remove — узел, document — name/viewport/state. Каждое изменение узла содержит ID и source, если ссылка имеется. Сам diff не является исполняемым патчем.

Последний applied может быть старее current. Обычное сохранение черновика не обновляет applied. Импорт очищает указатель, но не удаляет каталоги старых снимков. sourceRevision берётся из baseline и должен отражать прочитанные исходники, включая незакоммиченные изменения.

Для переноса прочитайте AGENT.md и поручение пользователя. Тестовые снимки не применяются к коду. Новый baseline создаётся после проверки разрешённого переноса.

## Передача v0.2 и совместимость

Ошибка файлового хранилища возвращает HTTP 500 с полем `error`; некорректные данные — 400, устаревшая revision — 409. Отказ записи draft, Apply или импорта не повышает revision и не меняет последний успешный applied. При обрабатываемой ошибке удаляются временный файл сессии и каталог неудачного Apply; при отказе самой очистки остаётся сообщение в терминале. GET `/api/handoff` возвращает согласованные метаданные, документ и отчёт одного снимка даже при параллельном Apply или импорте; этот снимок может уже не быть последним к моменту получения ответа.

Схема макета остаётся `schemaVersion: 1`. POST `/api/apply` принимает необязательное поле `mode`: `test` (по умолчанию) или `review`. Остальные значения отклоняются. Режим записывается в `applied.mode` и `changes.handoff.mode`, а не в props или дерево документа. Ревизии и sourceRevision сохраняют прежний смысл.

`report.md` содержит читаемое описание, режим, ревизию снимка, значения до/после и source. GET `/api/handoff` возвращает `{applied, document, report}` последнего снимка. UI сравнивает полное дерево снимка с current, не только номера ревизий. Обычный draft сохраняет прежние applied и report.

Старые сессии загружаются без миграции. Если режима нет, UI показывает «режим не указан», а отчёт консервативно считает снимок тестовым. GET handoff формирует отчёт из JSON, поэтому работает и со старым снимком без report.md. `review` означает подготовку к согласованию; сам файл не является поручением изменить код.

## Смещения и resize

Смещения визуальные, относительно места узла в контейнере; не меняют порядок, родителя и выделенное соседям место. Перемещение контейнера смещает и его детей. Верхняя/левая ручка resize компенсирует положение, чтобы противоположная граница оставалась на месте, поэтому diff может содержать одновременно размер и смещение. Боковая ручка сохраняет исходный режим высоты, верхняя — ширины. Weight удаляется только при фиксации размера вдоль основной оси родителя.

Новые редактор и сервер читают старые документы schemaVersion 1. Документы со смещениями требуют обновлённого редактора и сервера: прежний валидатор не знает offsetX/offsetY. Схема дерева, revision и sourceRevision не изменяются. Переносится намерение, а не браузерный CSS.

## Геометрия v0.2.2

Необязательное поле документа `layout`: `{ "mode": "free" | "auto", "frames": { "ID": { "parent": "ID родителя или null у корня", "x": 0, "y": 0, "width": 100, "height": 48 } } }`. parent в JSON — строка или null, не строка "null". frames необязателен, пустая карта допустима. Координаты ±16000 dp, размеры 0–16000 dp, числа конечные; ID и parent должны соответствовать дереву. Частичная карта допустима; узлы без frame используют обычную компоновку. Редактор сохраняет полную карту.

x/y относятся к внутренней границе родителя (после border, до padding), учитывают scroll и не содержат собственный offset узла. width/height — размеры border-box. В свободном режиме frames фиксирует размещение; числовые props.width/height переопределяют размеры кадра, offsetX/Y добавляются к его координатам. Остальные режимы размера фиксируются по измеренному кадру. Корень остаётся в потоке phone-body, его x/y справочные. В автоматическом режиме frames игнорируется.

Отсутствие layout означает свободный режим без ещё зафиксированных frames; первоначальное превью рассчитывается прежним renderer. Первый жест фиксирует геометрию. Переход free→auto удаляет frames, auto→free измеряет текущий вариант. Структурная правка сбрасывает frames и пересчитывает дерево, сохраняя offsets. Сброс возвращает baseline без ранее измеренных кадров. Старые снимки не мигрируются.

schemaVersion остаётся 1. Для корректного показа frames нужны сервер и клиент v0.2.2; старые версии могут проигнорировать новое поле и показать другое размещение. `diff.changes` включает document/layout, `diff.layoutMode` сообщает текущий режим. Frames — данные предполагаемого макета, не готовые Compose-модификаторы.

## Границы контейнера v0.2.3

В свободном режиме resize сверху/слева/углом сохраняет экранные позиции содержимого. При смещении начала контейнера на dx/dy координаты x/y его прямых детей в frames уменьшаются на dx/dy; собственные offsets детей сохраняются. Вложенных потомков повторно компенсировать нельзя: они наследуют исправленное начало прямого ребёнка. Поправка при жесте вычисляется от исходной геометрии, а не накапливается на каждом событии. Клавиатурный resize использует те же правила. Обычный drag контейнера не компенсирует детей — они движутся вместе с родителем. В автоматическом режиме сохраняется расчёт потока.

Новых полей и миграции нет: старые документы и снимки сохраняют существующие координаты. Новые жесты записывают исправленные frames в черновик и Apply. Для одинакового поведения жестов нужен клиент v0.2.3. Содержимое может оказаться за пределами уменьшенного контейнера; свободный режим не уменьшает его шрифты и размеры автоматически.

## Достоверность исходного макета

Baseline — реконструкция агентом, а не доказанный снимок Android UI. Diff между baseline и proposed отделяет изменения JSON, но не проверяет достоверность реконструкции. Ошибки baseline могут влиять на интерпретацию размеров и структуры; создание layout.frames фиксирует всё дерево без отдельного пользовательского изменения каждого узла. Перед переносом требуется сверка с настоящим экраном и согласование исходного макета по AGENT.md. Непроверенная или заведомо неточная сессия используется только как эскиз; Apply и review не подтверждают baseline. proposed — контекст, а не команда воспроизвести всё дерево. Эти ограничения пока обеспечиваются инструкцией агенту: сервер и UI не хранят подтверждение baseline и не блокируют снимок автоматически.

## Проверка baseline и намерение — v0.3.0

GET session возвращает baselineFingerprint (SHA-256 сериализованного baseline), метаданные reference и verification либо null. Само изображение хранится в локальной сессии, но не включается в GET session. reference: label, mime, digest (SHA-256 изображения), capturedAt. verification: baselineFingerprint, referenceDigest, confirmedAt, confirmedBy=user (или render: сессию создал `edit-previews` из JVM-отрисовки Preview, эталон — тот же кадр), sourceRevision, viewport, state. Подтверждение связывается с baseline, а не с текущим черновиком. Менять эталон после подтверждения означает повторную проверку. Без эталона, версии исходников либо совпадения fingerprint подтверждение запрещено. Agent не вызывает confirm вместо пользователя.

POST Apply mode=review без действительного подтверждения либо при подмене sourceRevision черновиком возвращает 422 без записи снимка и увеличения revision. test разрешён для эскизов. Старые сессии считаются неподтверждёнными; чтение старого review без verification также возвращает 422. Импорт очищает подтверждение, архивируя старую сессию; restore сохраняет заменённую сессию и возвращает прежние baseline/current/reference/verification/applied с новой revision.

В changes добавлены verification, reference и intent. intent.changes — свойства, дерево и явный переход режима; intent.technical — фиксация layout.frames. Полный changes.changes остаётся для совместимости. Снимок содержит reference.json (base64 изображения и метаданные), если эталон загружен. Handoff дополнительно возвращает baseline, verification, reference с URL именно этого снимка и intent. Поздние изменения и замена эталона их не меняют. Старые потребители могут игнорировать новые поля, но агент переноса обязан проверить verification и читать intent совместно с обоими деревьями.

viewport.presentation: content показывает область приложения без декоративной рамки/панелей; device и отсутствие поля сохраняют прежнее отображение. viewport.fontScale: 0.5–3, по умолчанию 1; задаёт масштаб для просмотра; при наличии нативной кривой используется измеренное преобразование sp→dp, исходные значения в sp сохраняются.

Новые props: fontFamily=system|Roboto|Roboto Flex|Sans Serif|Serif|Monospace|Cursive (можно наследовать от контейнера); letterSpacing от −5 до 20 sp; maxLines — целое 1–100; textOverflow=clip|ellipsis. Шрифты включены в пакет и загружаются только локально. Модель schemaVersion=1 сохраняется. Для точного исходника нужны настоящая типографика, состояние, fontScale, размеры и нативная геометрия; измеренные прямоугольники сами по себе не подтверждают верность содержимого.

Подтверждение также связано с bridgeVersion редактора. После обновления новое редактирование требует повторной визуальной сверки; исторический снимок сохраняет прежнюю проверку. Managed open заменяет работающий сервер прежней версии, сохраняя данные.

## Настоящий UI: compose-visual-bridge-native-v1

Native-сессия живёт в отдельном `native-session.json` выбранного BRIDGE_DATA. `/api/native` возвращает revision, frame без image, draft, applied, confirmedDigest, connection, previews и pendingFrame. PNG отдаётся через `/api/native/image?digest=<SHA>`; несовпадение digest возвращает 409. POST connect, disconnect, frame, confirm, draft, refresh, navigate, apply требуют текущую revision. Одновременные записи сериализуются с обычной сессией.

Вход — Buddy frame с type, preview, image, width, height, densityDpi и semantics. Wire-команды опубликованного runtime 0.3.0 используют `cmd`: requestPreviewList, rerender, navigate; сообщения — `type`: previewList/frame. Подключение loopback-only. Метаданные sourceRevision (40/64 hex), screenState и origin предоставляются для реально собранной сцены. Digest связывает изображение, измеренные узлы и эти метаданные; время съёмки не меняет digest. Вход ограничен по PNG, размерам, числу и глубине узлов; id должны быть уникальны.

Снимок `/api/native/handoff` / `read-native` содержит format, applied, frame с PNG base64, intent.changes, verification и requiresUserAuthorizationForCodeTransfer. Изменение содержит nodeId, property, value, nodeContext и source; sourceRequiresResolution всегда true. file/line имеют confidence hint либо unknown и не доказывают сопоставление с Kotlin. intent хранит только пожелания пользователя. Review требует подтверждения digest пользователем, test допускается без него. Снимок пишется атомарно в native-*/changes.json и сохраняет исходный кадр при дальнейших правках и рестарте.

Новые кадры при непустом draft ожидают в памяти и не подменяют базу правок. Навигация/переподключение/импорт блокируются до очистки draft. Повторный запуск не подключается к устройству автоматически. Перед переносом проверяйте sourceRevision и поручение пользователя; после переноса новая сборка и новый кадр обязательны для оценки результата.

## Каталог компилируемых Preview — compose-visual-bridge-catalog-v1

Подготовленный workspace отмечается .bridge-native-workspace.json (format=compose-visual-bridge-workspace-v1, sourceProject, module, toolchain, extraScenes). Это отдельная копия Git-root; исходный проект не содержит файлов Bridge. Build пишет bridge-native-build.json только после успешного assembleDebug и стабильного SHA исходных файлов. В результат входят sourceRevision, apk, apkSha256, previews, generatedRegistry, emptyReason и toolchain. Сгенерированный Kotlin registry сам по себе не является доказательством успешной компиляции.

Catalog проверяет текущие sourceRevision и SHA APK; устаревший результат отклоняется до подключения к устройству. Build запускает KSP discovery без incremental режима и требует JDK 21+. Значения previews — реальные FQN-ключи для BuddyPreviewActivity/navigate; они не являются перечнем всех экранов или всех @Preview-конфигураций. Неточное или отсутствующее source mapping элементов не исправляется наличием каталога. При подключении используйте SHA из успешного build установленного APK, после изменения источников повторите build и проверку каталога.

### Кандидаты исходников native UI

Необязательный `frame.sourceMapping` имеет формат `compose-visual-bridge-source-candidates-v1`, содержит `workspace`, `sourceRevision`, `apkSha256`, `requiresResolution: true`. `sourceFrameDigest` хранит digest исходного кадра до сопоставления; digest связанного кадра включает результаты поиска. `node.source.candidates` содержит до 12 объектов `{file, line, reason, excerpt, excerptStartLine, resource?}`, `candidateCount` — полное число мест. Пути относительны рабочей копии; строки начинаются с 1. Причины: `runtime-hint`, `text-literal`, `string-resource-reference`; ресурс содержит собственный файл/строку. `confidence: candidate` не означает доказанную связь; даже единственный кандидат требует проверки. `unknown` обозначает отсутствие найденного места. Старые кадры с `hint` без списка кандидатов совместимы.

POST `/api/native/source` принимает `{revision, digest, workspace}`, требует кадр без черновика, проверяет каталог и ревизию сборки, обновляет кадр и снимает подтверждение сцены. `/connect` и `/frame` также принимают необязательный `workspace`. Намерения сохраняют кандидатов и `sourceRequiresResolution: true`. Новые намерения и Apply повторно проверяют исходники и APK; прежняя передача читается без обращения к изменившейся рабочей копии.

### Полный native-редактор 0.7.0

Оба режима используют `public/index.html`; entry выбирает провайдер по `/native`. Native сохраняет настоящий PNG и его bounds. Желаемые смещения и размеры показываются отдельной рамкой; они не заменяют исходный кадр и не являются доказательством результата Compose. Все намерения продолжают содержать context/source и `sourceRequiresResolution: true`.

Поддерживаются text, fontSize, lineHeight, fontWeight (100–900), fontFamily, letterSpacing, color, background, borderColor, borderWidth, width/height (число, auto или fill), offsetX/Y, padding, paddingHorizontal/Vertical, gap, radius, opacity (0–1), weight, alignX/Y, align, justify, textAlign, layoutMode и note. alignX/Y: start/center/end; align дополнительно stretch; justify дополнительно space-between; textAlign дополнительно justify; layoutMode: free/auto. Отсутствие намерения layoutMode означает сохранение исходной компоновки. Неизвестное свойство не заполняется выдуманным исходным значением.

Структура: remove=true для некорневого узла; moveTo={parentId,index} для существующего родителя, без циклов в итоговом графе; addChild=[{type,text,properties}] для 1–20 новых элементов (одиночный объект старого формата также принимается). Типы: Text/Button/Card/Column/Row/Box/Image/Spacer. Свойства нового элемента проверяются тем же валидатором; вложенные структурные операции не поддерживаются. Новые узлы обозначаются в клиенте как ожидающие переноса. Resize контейнера со стороны начала координат добавляет обратные offsetX/Y непосредственным детям одной пакетной операцией.

POST `/api/native/history` принимает {revision,direction:undo|redo}. Сервер хранит до 100 компактных состояний истории, повторно проверяет намерения при восстановлении и очищает redo при новой ветке. Публичное history={undo,redo} содержит счётчики. Новый кадр/привязка исходников сбрасывают историю. Сохранение черновика сериализовано; Apply ждёт последней записи. Конфликт/ошибка записи блокируют передачу и сохраняют локальную копию для восстановления.

GET `/api/native/export` возвращает исходный Buddy wire frame для повторного импорта; текущие пожелания его не изменяют. После новой сборки comparisonFrame загружается из последней неизменяемой передачи только для той же Preview/сцены с другой ревизией исходников. GET `/api/native/image?version=before&digest=…` выдаёт соответствующий исходный PNG. Кадры другой сцены не сравниваются как результат этой правки.

В пользовательском интерфейсе одна кнопка «Передать агенту», без выбора test/review. Режим снимка выбирается автоматически по актуальному подтверждению исходного экрана и sourceRevision; сведения о проверке сохраняются для агента. Передача всегда сохраняет снимок, сама не запускает агента и не изменяет исходники. Контракты API test/review сохраняются для совместимости.

Sans Serif, Serif, Monospace и Cursive соответствуют стандартным семействам Android Compose; браузер использует соответствующие системные семейства. Конкретные гарнитуры могут отличаться между устройствами. Roboto Flex требует ресурсного адаптера для Kotlin. Пользовательские шрифты проекта пока не импортируются автоматически. Явные width/height=auto задают размер по содержимому, включая свободный режим; сохранённый frame не должен подменять auto фиксированным размером.

## Runtime-сцена Compose

Дополнительный формат `document.compose.format = "compose-visual-bridge-runtime-scene-v1"` совместим с schemaVersion 1 редактора. `workspaceRevision` хранит ревизию восстановленной копии, `sourceHashes` — хеши инструментированных файлов. `calls` сопоставляет стабильные ключи определениям/местам вызова, включая области собственных компонентов. `bindings` связывает ID HTML-элемента с `runtimeIdentity`, исходным вызовом, доступным состоянием selected/disabled и `agentOnly: true`. `source.instance` сохраняет полную идентичность экземпляра; префиксы областей разрешаются через `compose.calls`.

`capture.sourceRevision` относится к инструментированной сборке, `viewport.fontScale` — к фактической плотности шрифта Android, `state` — к имени выбранной сцены и Preview. Геометрия узлов измерена в dp; нативная метрика высоты текста нормализуется по fontScale. Браузер по-прежнему требует сравнения с эталоном.

Любое изменение дерева или расположения такой сцены добавляет `transfer.requiresAgent` для всей сцены, включая удаление и изменения одних только координат. `compose-plan` возвращает стратегию agent для подтверждённой передачи; прямой `composePatch` runtime-сцены отклоняется. Статический Compose-формат и обычные JSON-документы сохраняют прежнее поведение. Автоматический запуск агента не добавлен.


### Измерения runtime-текста и кнопок, 0.8.3

Необязательные `compose.capture.fontScale` и `fontScaleCurve` связывают измерения с масштабом Android. Кривая содержит 301 целое значение в сотых dp для 0, 0.5, …, 150 sp; значения не убывают, первое равно 0. Браузер интерполирует дробные sp. При изменении viewport.fontScale старые измерения не применяются; без кривой сохраняется линейное масштабирование.

В `textGeometry[id]` дополнительно сохраняются `lineCount`, `layoutWidth` (dp), `lineAdvance` (расстояние между нативными baseline в dp) и `lineRanges`: `{start,end,ellipsis}` для каждой видимой строки. Индексы — UTF-16 относительно полного `text`, end исключён, без завершающих пробелов. Helper сохраняет границы до 50 строк; при большем количестве используется обычный HTML с обязательной проверкой эталона. Измеренная одна строка не переписывает исходный maxLines=2. При неизменных тексте, типографике и ширине HTML показывает измеренные переносы и многоточие; после правки возвращает обычное CSS-размещение до следующего Android-захвата. TextLayoutResult-callback исходника вызывается после сохранения измерений.

`fontDp` — фактический размер шрифта из плотности и стиля TextLayoutResult, положительное число до 1000 dp. Он имеет приоритет над общей кривой sp при совпадении текста и семейства/начертания; изменение fontSize масштабирует его относительно захваченного sp. Исходный props.fontSize остаётся в sp. Разрешённый letterSpacing из TextLayoutResult переводится из em в sp и сохраняется в props и метриках, чтобы браузер не подменял фактический стиль значением по умолчанию.

`lineWidths` — ширина каждой строки TextLayoutResult в dp, включая нативное многоточие. Массив соответствует lineRanges; значения конечные, от 0 до 16000. После загрузки локального шрифта HTML согласует горизонтальный масштаб каждой неизменённой строки с измеренной шириной. Выравнивание использует эту же ширину. Это сохраняет нативные метрики конкретного захвата, не обещая одинаковой растеризации Android и Chromium. Изменение текста, типографики, ширины или viewport.fontScale отключает сохранённые ширины вместе с переносами. `textBoxWidth` сохраняет ширину самой нативной подписи в dp (0–16000), отдельно от внешней области кнопки. При неизменённом baseline весь текстовый блок кнопки центрируется внутри области нажатия, а строки внутри блока сохраняют выравнивание текста; дополнительная компенсация верхнего leading применяется только к Text, поскольку Button уже центрирует блок по вертикали.

`paintInsets: {left,top,right,bottom}` — неотрицательные dp между внешней областью кнопки и её видимой областью. Заливка/рамка рисуются внутри, область выбора и геометрия остаются внешними. Для free-кадров x/y детей отсчитываются от внутреннего края рамки родителя; bindCapture/bindScene вычитают borderWidth из нативной разницы координат. Отрицательные значения допустимы: Compose может размещать содержимое у внешнего края декоративной рамки.

Новые поля совместимы со schemaVersion=1. Старые снимки сохраняют прежнее отображение; для точного измеренного текста и кнопок требуется новый захват, без замены пользовательского черновика.


`compose.capture.fontHashes` может содержать `Roboto: <64 hex SHA-256>` системного файла шрифта, выбранного TextRunShaper для Typeface.DEFAULT (API 31+). Встроенные неизменённые версии 3.005 и 3.015 выбираются по известному хешу; неизвестный/отсутствующий хеш сохраняет прежний Roboto и требует проверки эталона. Значение props.fontFamily остаётся `Roboto`, рассчитанное CSS-семейство не переносится в Kotlin.

`paintVisible=false` у кнопки означает отсутствие видимой области в нативном кадре при пересечении её raw-геометрии с viewport (например, полностью отсечённый последний чип в узком Row). Декорация и подпись скрыты, геометрия и дерево сохранены; изменение текста/типографики/ширины снимает использование старого измерения. Для полностью находящихся вне viewport элементов этот флаг не ставится. Подписи кнопок также измеряются через их единственный вложенный Text без добавления отдельного редактируемого ребёнка.

## Результат переноса и история — 0.8.4

HTML/model и Compose-сессии принимают `POST /api/result`; отдельный nativeOnly PNG-редактор пока этот путь не использует. Запрос содержит текущую `revision`, `snapshot` (точный applied.directory), `beforeSourceRevision`, `status` (`succeeded` или `failed`) и краткий `message`. Снимок должен оставаться последним Apply, а beforeSourceRevision — совпадать с baseline сохранённого снимка. Устаревший снимок отклоняется с 409. Принятый результат нельзя перезаписать для того же снимка.

Для успеха обязательны `sourceRevision`, новый `document`, `reference: {mime,image,label}` с настоящим кадром и `checks: {build,visual}` с описанием выполненных проверок. Ревизия документа совпадает с sourceRevision и отличается от исходной; root.id и формат Compose относятся к тому же экрану. Проверки — отчёт агента: сервер не выполняет Gradle и не удостоверяет происхождение изображения. Агент обязан проверить исходники, сборку и настоящий кадр перед записью. Для failure документ и кадр не требуются; baseline, current и история сохраняются.

Результат записывается в отдельный неизменяемый `transfer-<UUID>.json`; session хранит публичные `result` и `results`. `GET /api/result` возвращает последний результат и applied. `GET /api/results/<ID>/reference` возвращает его кадр. Summary включает status/message, обе ревизии, проверки, режим исходного снимка, время записи, fingerprint нового документа и ссылки на нативные кадры до/после. Запись метаданных результата не повышает edit revision, поэтому не делает конфликтным уже отправляемый поздний draft. Проверка revision и сериализация записи при этом сохраняются. Handoff и каталог applied не изменяются.

Пользователь смотрит кадры и нажимает «Принять результат». `POST /api/result/accept` с `{revision,id}` принимает только актуальный успешный результат для последнего Apply. Транзакция архивирует прежнюю сессию, устанавливает новый baseline/reference и повышает revision. Подтверждение baseline сбрасывается: результат агента не заменяет пользовательскую сверку нового исходника. Другие окна сохраняют свои локальные правки и получают обычный конфликт revision при следующей записи.

Поздние правки вычисляются относительно proposed именно этого снимка. Переносятся изменения props, viewport, названия и отдельных полей frames, если идентичность элемента сохранена, а новое исходное значение совпадает со старым proposed либо уже равно желаемому. Для runtime Compose нужна та же runtimeIdentity. У статического Compose без стабильной идентичности поздний черновик архивируется. Структурные изменения, конфликт значения, отсутствующий элемент или изменение связи/метаданных сохраняют **весь** поздний черновик отдельно, без частичного применения. Summary сообщает `lateDraft.status` (`none`, `rebased`, `archived`), причины и каталог архива. Кнопка «Вернуть поздний черновик» восстанавливает прежнюю сессию вместе с её историей; принятый результат тоже остаётся в обратном архиве.

Сессия дополнительно хранит `history: {past,current,future}`. Draft/Apply принимают историю, current которой равен отправленному document. Все документы проверяются, принадлежат одной sourceRevision/root.id; всего до 100 прошлых/будущих состояний, история до 8 MB. Перед сохранением старейшие состояния обрезаются до лимита UTF-8, текущий документ и ближайшие действия сохраняются. Документ остаётся ограничен 2 MB; совокупный запрос draft/Apply — 12 MB. Старые клиенты без history продолжают работать, сервер добавляет обычный commit. Старые сессии открываются с пустой историей. Reload/restart восстанавливают Undo/Redo с сервера; локальный cache сохраняет историю несохранённых правок. Принятие результата создаёт границу истории на новом baseline: перенесённый поздний черновик становится одним отменяемым шагом, полная прежняя история остаётся в архиве. schemaVersion документов остаётся 1.

## Каталог экранов и палитра — 0.9.0

Управляемая сессия содержит отдельный project-context.json формата compose-visual-bridge-project-v1 с каноническим project и home данных. Его создаёт CLI плагина; пути проекта не принимаются от браузера. В автономном сервере без этого файла каталог скрыт. Каждой сцене принадлежит самостоятельный session.json, история, эталон и applied.

GET /api/project возвращает managed, activeSession, sessions, palette и live. Перед переходом браузер дожидается сохранения черновика. Ответ содержит URL управляемого сервера; старый сервер и данные не удаляются. Каталог ограничен тем же проектом. Это черновик нового экрана, без готовой связи с Android. Его Kotlin и навигацию создаёт агент после поручения; подтверждение существующего проекта из этой метки не следует.

Палитра имеет format=compose-visual-bridge-palette-v1, sourceRevision и components (до 100): уникальный id, name, валидный node со source.file/source.symbol. В transfer.requiresAgent такой новый экземпляр отмечается projectComponent; шаблон отображения не даёт разрешения переписать собственный Kotlin-вызов. Новому экрану соответствует screen. Старые сессии без этих полей читаются без миграции.

Live-адаптер создаёт debug-копию с сохранёнными Kotlin/KSP, отдельным суффиксом APK и тестовой подписью. Захват текущей сцены содержит captureId, capturedAt, semantics и настоящий PNG; SHA установленного APK сверяется с сохранённой сборкой. Новый captureId создаёт отдельную сессию, повторный возвращает её черновик. Привязки используют явные key и instance; повторный ключ, отсутствующий корень и stale-состояния блокируют создание сессии. Системная тема фиксируется отдельно от собственной темы приложения. Эти файлы, подпись и снимки не входят в пакет.

## Идентификатор live-запуска — 0.9.1

Новая .bridge-live.json сохраняет captureProtocol=2. При live-run создаётся UUID launchId в контексте и приватном файле приложения files/compose-visual-bridge-live-launch.txt; directory создаётся с UID тестового приложения. Это изменение prepared-стенда, не миграция пользовательских session.json/applied.
