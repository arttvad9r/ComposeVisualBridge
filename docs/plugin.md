# Плагин Compose Visual Bridge для Codex и Claude Code

Плагин содержит готовый редактор, локальный сервер и два skill: настройку и работу с экраном. Пользователю не нужны npm install, ручные ссылки skills, выбор PORT или BRIDGE_DATA. Для основного пути edit-compose/edit-scene нужен Node.js 22+ со встроенным WebSocket. Базовый JSON-редактор и setup работают на Node.js 20+. Проверено в Linux, Codex CLI 0.159.2 и Claude Code 2.1.285; Windows и macOS пока не проверены.

## Установка

В этом checkout пакет уже собран в `dist/compose-visual-bridge`. Источник «Compose Visual Bridge» объявлен в `.agents/plugins/marketplace.json`. Откройте этот проект в Codex, перезапустите приложение, затем в каталоге плагинов выберите этот локальный источник и установите Compose Visual Bridge. Пакет не опубликован в общем каталоге.

Для передачи на другой компьютер используйте `dist/compose-visual-bridge-0.9.2.tgz`. Распакуйте архив в выбранный каталог: он содержит готовый плагин и локальный marketplace. Подключите этот каталог как источник через `codex plugin marketplace add /absolute/path/to/unpacked-directory`, затем установите плагин из каталога приложения. Ручное размещение skills не требуется. Команды подключения изменяют пользовательскую настройку Codex — в рамках разработки они автоматически не выполнялись.

После установки выполните настройку плагина. Она проверяет Node.js и комплектность сборки, не создаёт макеты и не запускает npm. Установка через штатный CLI, обнаружение включённых skills и setup из установленного пакета проверены в отдельном профиле Codex; установка кнопкой в приложении и автоматический вызов настройки после установки пока не проверены.

### Claude Code

Пакет содержит манифест `.claude-plugin/plugin.json`, а сборка создаёт локальный marketplace `dist/.claude-plugin/marketplace.json`; оба входят в архив. Подключение из этого checkout или распакованного архива:

```sh
claude plugin marketplace add /absolute/path/to/dist
claude plugin install compose-visual-bridge@compose-visual-bridge-local
```

Начните новую сессию Claude Code. Skills доступны как `/compose-visual-bridge:setup` и `/compose-visual-bridge:compose-visual-bridge`; Claude также вызывает их по описанию запроса. Автоматического onboarding, как в Codex, нет: после установки попросите «Проверь настройку Compose Visual Bridge». Удаление: `claude plugin uninstall compose-visual-bridge@compose-visual-bridge-local`; данные сессий остаются. Установка в изолированный профиль, setup → create → open → правка и передача в браузере → read → stop → повторный open проверены: [отчёт](verification/claude-plugin-2026-10-12.md).

## Обычная работа

1. В чате нужного Android-проекта: «Используй Compose Visual Bridge: открой экран настроек в визуальном редакторе».
2. Агент читает исходники и состояние, подготавливает макет, создаёт отдельную сессию и открывает локальный редактор.
3. Откройте проверку исходника, сравните макет со снимком настоящего экрана и подтвердите его. При неточности агент готовит отдельную исправленную сессию. Затем измените макет и нажмите «Передать агенту».
4. Поручите агенту прочитать снимок и, если нужен перенос, применить правки к исходникам и проверить результат в Android.

«Продолжи редактирование в Bridge» возобновляет последнюю сессию проекта. Открытие уже работающей сессии возвращает тот же сервер. Для другого экрана создаётся новая сессия; прежняя сохраняется. Это ещё не каталог всех экранов приложения. Сервер работает в фоне, поэтому завершение команды не закрывает редактор. По просьбе остановить Bridge агент выполняет stop; закрытие вкладки само по себе сервер не останавливает.

Веб-превью приблизительное, макет по Kotlin создаёт агент. Тестовый снимок и режим review не являются поручением изменить код. Импорт поверх существующих пользовательских правок требует согласованного действия. Инструкции: AGENT.md и docs/protocol.md включены в пакет.

## Данные и обновление

Сессии хранятся в `${XDG_DATA_HOME}/compose-visual-bridge`, по умолчанию `~/.local/share/compose-visual-bridge`. Каждому каноническому пути проекта соответствует отдельный каталог. Переменная BRIDGE_HOME переопределяет корень для тестов и специальных установок. В каталоге проекта есть latest.json и screen-*/data с session.json, applied-*, server.log и runtime.json.

Данные находятся вне установки плагина. Обновление или удаление пакета не удаляет макеты. Перед обновлением попросите агента остановить сервер; следующий open использует новую установленную сборку. Перемещение Android-проекта меняет ключ каталога, автоматическая миграция пока отсутствует: сохраните предыдущий путь данных и экспортируйте макет перед переездом.

Перед удалением плагина остановите его серверы. Затем удалите пакет через Codex; пользовательские данные остаются. Для удаления конкретной сессии сначала остановите её, затем удалите только её screen-* каталог. Данные и снимки не добавляйте в Git.

## Команды внутри установленного пакета

Все команды выполняются агентом по абсолютному пути к плагину:

```sh
node /path/to/plugin/scripts/plugin.mjs setup
node /path/to/plugin/scripts/plugin.mjs create --input /path/to/layout.json --project /path/to/android-project
node /path/to/plugin/scripts/plugin.mjs list --project /path/to/android-project
node /path/to/plugin/scripts/plugin.mjs reference --input /path/to/native.png --label "Экран, состояние, устройство" --project /path/to/android-project
node /path/to/plugin/scripts/plugin.mjs open --project /path/to/android-project
node /path/to/plugin/scripts/plugin.mjs read --project /path/to/android-project
node /path/to/plugin/scripts/plugin.mjs stop --project /path/to/android-project
```

Если --project не указан, используется текущий каталог. Для предыдущей сессии добавьте --session с идентификатором, возвращённым create/open. read при необходимости запускает сохранённую сессию и возвращает applied, baseline, document, verification, reference, intent и report одного снимка. list возвращает сохранённые экраны и их идентификаторы. reference загружает эталон, но не подтверждает макет вместо пользователя. Порт и путь данных из ответа open не нужно передавать другим командам.

Команды сериализуют управление одной сессией, повторно используют работающий процесс и освобождают lock после корректной остановки. После отказа запуска смотрите server.log. Не запускайте старый ручной CLI или server.mjs поверх данных управляемой сессии. После SIGKILL или отказа диска может потребоваться ручная диагностика; не удаляйте lock живого процесса.

## Разработка и проверка

`npm run package:plugin` собирает браузерные модули, копирует разрешённые runtime-файлы, инструкции и legal notices, формирует переносимый marketplace и tgz. В пакет не попадают node_modules, пользовательские данные или тестовые результаты. Требуется системный tar на машине сборки; потребителю npm и esbuild не нужны. Исходный CLI scripts/bridge.mjs сохранён для разработки и совместимости.

`npm test` собирает пакет и проверяет его после распаковки и переноса в каталог с пробелами, конкурентный open, изоляцию проектов, неизменность снимка, stop, повторный запуск и сохранность данных при удалении установленной копии. Во встроенном браузере Codex отдельно проверен UI Apply собранного редактора. [Результат проверки](verification/codex-plugin-2026-10-11.md).

Формат пакета и локального каталога основан на [официальной документации Codex](https://developers.openai.com/plugins/build/plugins). Установка в публичный каталог и MCP не входят в этот этап.

## Проверка и восстановление

В editor кнопка состояния исходника открывает сравнение эталона и baseline. PNG/JPEG/WebP до 8 MB хранится локально, отдельная копия включается в снимок. Агент не нажимает подтверждение вместо пользователя. Новый эталон или импорт снимает подтверждение; старый снимок остаётся неизменным. Для переноса дополнительно требуется поручение пользователя и сверка исходников.

Импорт архивирует исходный макет, черновик, эталон, подтверждение и указатель снимка. «Вернуть предыдущую сессию» восстанавливает их и сохраняет заменённый вариант. Два сервера не могут открыть один каталог данных. После аварийной остановки managed open удаляет только lock мёртвого сервера; lock живого процесса не снимается.

Установка в основной профиль пользователя во время разработки не выполнялась. Для установки архива через CLI после добавления marketplace: `codex plugin add compose-visual-bridge@compose-visual-bridge-local`. Штатный формат описан в [документации OpenAI](https://developers.openai.com/plugins/build/plugins).

Подтверждение также связано с bridgeVersion редактора. После обновления новое редактирование требует повторной визуальной сверки; исторический снимок сохраняет прежнюю проверку. Managed open заменяет работающий сервер прежней версии, сохраняя данные.

## Настоящий Compose UI

Нужен Node.js 22+ для WebSocket и Android debug-адаптер Compose Buddy. Это отдельный режим: агент вызывает оригинальный экран с тестовыми данными, редактор получает PNG и дерево элементов. HTML-реконструкция не нужна. Первичное подключение описано в [инструкции](native-ui.md); архив содержит её и команды адаптера, Android SDK и Buddy в архив не включены.

```sh
node <plugin>/scripts/plugin.mjs create-native --project <проект>
node <plugin>/scripts/plugin.mjs native --project <проект> --endpoint ws://127.0.0.1:37890/ --source-revision <SHA> --state "Настройки, ru, светлая тема, тестовые данные"
node <plugin>/scripts/plugin.mjs read-native --project <проект>
```

Используйте session из create-native, если одновременно открыты несколько экранов. open возобновляет native-сессию и возвращает nativeUrl; переход по корневому url тоже открывает настоящий UI. read-native читает последний неизменяемый снимок, а не текущий черновик.

## Подготовка Preview без ручного registry

Команды prepare-native, native-build и native-catalog входят в пакет 0.7.0. Они подготавливают отдельную копию Git-проекта, включают Buddy KSP только для debug и возвращают каталог компилируемых Preview с ревизией и SHA APK. Требуется JDK 21; описание поддерживаемой структуры и параметры — в [native-ui.md](native-ui.md). SDK и зависимости Gradle устанавливаются вне плагина. Пустой каталог требует тестовых сцен оригинального экрана, а не HTML-реконструкции.

В 0.7.0 добавлена команда `source-native --workspace <копия>` и просмотр Kotlin-кандидатов выбранного элемента. Редактор проверяет ревизию сборки и сохраняет найденные места в native-передаче; совпадение текста не выдаётся за точный source map.

## Версия 0.7.0

Настоящий UI открывается в полной общей оболочке редактора. Для подготовленной Android-копии native-run автоматически проверяет APK/SHA, устанавливает его на указанный тестовый эмулятор, запускает оригинальный Preview и возвращает nativeUrl. Setup отдельно сообщает готовность Android toolchain. Undo/Redo, свойства, дерево, жесты и сравнение работают в native-режиме; Kotlin меняется только после поручения на перенос. Обновление пакета не изменяет уже сохранённые данные сессии; новую установленную версию skills используйте в новой беседе.

## Рабочая версия 0.9.1

Новый Compose-импорт хранит внешние размеры и порядок Modifier; браузер учитывает область background после padding и заполнение Box. Старые снимки сохраняются, изменённый старый импорт требует новой отдельной сессии. [Проверки геометрии 0.8.2](verification/geometry-fixes-2026-10-11.md).

Пакет включает браузерный Compose-импорт и runtime-сцены; ограничения описаны в [инструкции](browser-compose.md). Исправления аудита защищают UTF-8, актуальный черновик перед импортом и восстановление Kotlin после отказа записи. Автоматический перенос сохраняет место существующего Modifier в цепочке, заменяет отступы по осям и поддерживает сброс enabled; неоднозначные цепочки требуют работы агента. Ошибка native-операции остаётся видимой после опроса сервера. [Результаты проверки и оставшаяся Android-приёмка](verification/audit-fixes-2026-10-11.md).


В 0.8.3 runtime-захват сохраняет границы и ширины строк, многоточие, межстрочный шаг, фактический размер шрифта и нативную шкалу sp→dp. HTML учитывает видимую область Material-кнопки внутри области нажатия и внутренний край CSS-рамки. Эти измерения используются при совпадении текста, типографики и ширины; правка возвращает обычный расчёт текста до нового захвата. Старые сессии читаются без миграции; для новых измерений нужен новый импорт в отдельную сессию.

Приёмка 0.8.3 на полном SettingsScreen: [два переноса и расширенные состояния](verification/mealio-acceptance-2026-10-12.md), 71 Node-тест и 55 Chromium-сценариев. Проверены callbacks, темы, длинные строки и fontScale 160%. Приёмка установленного плагина и полного сценария экранов остаётся в шагах 5–6 плана готовности.

## Результат переноса — 0.8.4

`result --project <проект> --session <ID> --input <результат.json>` записывает успех или сбой для конкретного applied-снимка. Формат описан в [протоколе](protocol.md#результат-переноса-и-история--084). Пользователь видит сообщение и нативные До/После, принимает результат отдельной кнопкой; новый baseline не подменяет поздний черновик. Сохранённая история переживает reload/restart, неоднозначные поздние правки можно вернуть из архива. Команда не запускает агента, Gradle или перенос в код.

[Приёмка цикла результата 0.8.4](verification/transfer-result-2026-10-12.md): 75 Node-тестов и 56 Chromium-сценариев; CLI проверен из распакованного пакета текущей версии.

## Экраны и палитра — 0.9.0

В редакторе управляемой сессии выбирайте сохранённый экран и состояние. Перед переходом текущий черновик сохраняется; история и снимки принадлежат каждой сессии отдельно. «Новый экран» создаёт пустой черновик, необязательный запрос остаётся в его документе. Агент подключает Kotlin, навигацию и поведение после поручения. Палитру собственных компонентов готовит агент по исходникам и регистрирует командой `palette`; вставка сохраняет связь с компонентом проекта.

Для работающего приложения предусмотрен [debug-адаптер](live-app.md). Нативные переходы, тема и динамический список на втором проекте ещё требуют приёмки; сборка адаптера сама по себе её не подтверждает.

[Проверки 0.9.0 и оставшаяся приёмка](verification/screens-plugin-2026-10-12.md). CLI-установка и обновление/откат выполнены в отдельном профиле; пользовательская установка не менялась.
