# Редактирование экрана работающего приложения

В 0.9.0 добавлен отдельный debug-адаптер текущей Compose-сцены. Это путь через обычную Activity и навигацию приложения. Каталог Preview остаётся самостоятельным способом подготовки воспроизводимых сцен. Нативная приёмка нового пути на втором проекте ещё не завершена; успешная сборка не подтверждает достоверность каждого экрана.

## Пользовательский сценарий

Агент подготавливает отдельную debug-копию и связи с исходниками. В этой копии пользователь переходит на нужный экран обычными средствами приложения и нажимает «Редактировать экран». Захват сохраняет настоящий PNG, semantics и измерения текста текущей сцены. Агент выполняет `edit-live`; в уже открытом редакторе доступна кнопка «Редактировать экран приложения».

В debug-копии захват запускает компактная кнопка с карандашом в нижнем правом углу. Её доступное название — «Редактировать экран»; она учитывает системные отступы и не закрывает кнопку сохранения в верхней панели. Название после захвата сообщает результат операции.

Новый захват создаёт отдельную сессию. Повторное открытие того же captureId возвращает прежнюю сессию с её черновиком. Переключение между сохранёнными экранами сначала сохраняет текущие правки; Undo/Redo и Apply каждого экрана независимы. Снимок не запускает агента и не меняет код.

Если агент создал захват, пока редактор уже открыт, каталог обновляется при возврате в окно. Кнопка «Обновить список» также перечитывает каталог. Обновление сохраняет выбранную сессию и текущий черновик.

## Подготовка агентом

Используйте выделенный тестовый эмулятор. На этой машине его аренду обеспечивает `android-emu`; не используйте чужую аренду или физический телефон. Читайте исходники, состояния, тему и требования выбранного проекта. Основной проект не меняется.

Команды внутри установленного пакета:

```sh
node <plugin>/scripts/plugin.mjs prepare-live --project <Git-проект> --adapter <JSON> --sdk <SDK>
node <plugin>/scripts/plugin.mjs live-run --project <проект> --serial <выделенный эмулятор>
node <plugin>/scripts/plugin.mjs edit-live --project <проект>
```

`prepare-live` может сразу запустить приложение, если передан `--serial`. Без него команда только собирает копию. `--output` резервирует новый каталог, существующий не заменяется. Установка плагина, исходный проект и сессии не используются как каталог копии.

Первый поддерживаемый вариант: application-модуль с обычным Kotlin DSL и явно заданными версиями Kotlin. В live-копии версии Kotlin/KSP сохраняются, Buddy/KSP Preview не добавляется. Debug APK получает суффикс `.composebridge` и отдельный тестовый ключ внутри копии. Нужны JDK 21, SDK и совместимая Compose UI с GraphicsLayer (проверена компиляция на 1.7.6). Подпись пользователя не читается. Ключ, APK и рабочая копия не входят в распространяемый пакет.

## Адаптер

Формат `compose-visual-bridge-live-adapter-v1` использует правила `calls` из runtime-сцены, описанной в [browser-compose](browser-compose.md). Несколько экранов могут иметь разные `root: true`; в одном захвате должен присутствовать ровно один корень. У каждого правила нужен явный стабильный `key`. Повторяющиеся экземпляры различайте через `instance` с идентификатором данных, например `subscription.id`. Для повторяемого собственного вызова `scope` также принимает `instance`. Тексты, индекс строки и semantics ID не доказывают идентичность экземпляра.

Дополнительно задайте `host`:

```json
{
  "format": "compose-visual-bridge-live-adapter-v1",
  "host": {
    "file": "app/src/main/java/example/MainActivity.kt",
    "fileHash": "SHA-256 прочитанного файла",
    "call": "ProjectApp(viewModel)"
  },
  "calls": []
}
```

В настоящем адаптере `calls` содержит проверенные связи всех поддерживаемых элементов нужных экранов. `host.call` должен встречаться ровно один раз; host-файл не включается в правила экранов. Оболочка `BridgeLiveHost` добавляется только для сборки debug APK. После сборки host и инструментированные исходники восстанавливаются; приложение продолжает работать из APK. Для Text внутри Button не создавайте вторую независимую привязку, если его layout callback уже собирает правило Button.

Button представляет весь вызов одним листом модели: его внутренние Text, Icon и Spacer сохраняются в Kotlin, но не получают отдельные правила адаптера. prepareScene отклоняет такие явно вложенные правила до инструментирования. Связи через собственные функции дополнительно проверяются по настоящему semantics-дереву во время захвата.

`edit-live` проверяет ревизию восстановленной копии, SHA локального и установленного APK, captureId и идентификатор текущего запуска. Неизвестный или повторный runtime-ключ, отсутствующий корень и устаревшая сборка отклоняются до создания новой сессии. Каталог и незавершённый черновик сохраняются при ошибке.

## Границы

Привязки подготовлены агентом по исходникам; адаптер не извлекает произвольный Kotlin автоматически. Полноту дерева, собственные ресурсы, шрифты и состояния нужно проверить по настоящему кадру. Неизвестные и невидимые графические ресурсы не восстанавливаются догадкой. Системная тема в состоянии захвата обозначает конфигурацию Android; собственную тему приложения и бизнес-состояние сверяйте отдельно.

Кнопка захвата доступна только в собранной debug-копии. Она сохраняет кадр локально в files приложения; `edit-live` читает его через `run-as` на выбранном эмуляторе. Сетевой сервис и внешний runtime-пакет для live-захвата не нужны. Для другой сборки подготавливайте новый стенд и актуализируйте адаптер. Перенос runtime-снимка, компонентов палитры и нового экрана выполняет агент после поручения; навигация и бизнес-логика остаются его задачей.

## Пустой кадр — 0.9.2

Перед снимком helper перезаписывает слой и ждёт два кадра. Если offscreen-рендер слоя всё равно вернул прозрачное изображение (так было на эмуляторе с gfxstream после смены темы), helper на время скрывает кнопку и копирует уже показанное окно через PixelCopy (Android 8+). edit-live отклоняет полностью прозрачный PNG с просьбой повторить захват. Для нового helper нужна новая prepare-live.

## Восстановление и свежесть захвата — 0.9.1

Host восстанавливается и при ранней ошибке подготовки адаптера. Если host изменился параллельно, новые правки сохраняются; при двойном отказе диагностика содержит причины подготовки и восстановления.

Новые debug-сборки имеют captureProtocol=2. live-run создаёт launchId в приватном files приложения до запуска Activity; helper добавляет его в кадр. edit-live требует совпадения с текущим запуском, независимо от часов Android и хоста. startedAt/capturedAt остаются диагностическими данными. Для live-run прежнего APK нужна новая prepare-live; сохранённые браузерные сессии не мигрируются и не удаляются. Старые захваты без launchId читаются по прежней проверке времени, если сохранённый контекст запуска также не содержит launchId.
