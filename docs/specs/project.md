# Спецификация Compose Visual Bridge

Статус: описание текущего прототипа и требований к следующему рабочему выпуску. Область: локальный редактор Android Compose-макетов и передача намерения агенту. Требования с пометкой «следующий этап» ещё не реализованы.

## Цель и сценарий

Дать пользователю возможность показать желаемые изменения интерфейса руками, без написания подробного текстового задания. Агент читает экран, готовит редактируемое представление, пользователь меняет его и передаёт снимок. Агент сопоставляет изменения с актуальным кодом, реализует их и проверяет настоящий экран.

Редактор запускается в браузере. Файлы и HTTP API обеспечивают совместимость с разными агентами. Первый адаптер — ручная подготовка JSON агентом для Jetpack Compose. Поддержка других UI-стеков возможна позже, но не является требованием первого выпуска.

## Требования и приёмка

| ID | Требование | Наблюдаемый результат | Статус |
|---|---|---|---|
| R1 | Загружать JSON с деревом, уникальными ID, состоянием экрана, viewport и sourceRevision | Валидный файл открывается; некорректный не заменяет сессию, ошибка видна | Реализовано |
| R2 | Сохранять связь элемента с конкретным экземпляром исходного UI | Diff содержит ID и source; агент различает повторяющиеся компоненты | Реализовано на уровне модели; ссылки готовит агент |
| R3 | Редактировать текст, типографику, размеры, цвета, отступы и выравнивание | Свойства отражаются в превью и diff; textAlign независим от положения блока | Реализовано |
| R4 | Давать понятные русские настройки и компактную панель | Разделы раскрываются; режимы размера имеют названия и объяснение; технические имена допустимы | Реализовано |
| R5 | Менять порядок и родителя перетаскиванием и кнопками | Видны линия/рамка и назначение; дерево не допускает циклов; отмена возвращает структуру | Реализовано; усиление надёжности — следующий этап |
| R6 | Сравнивать исходный и предлагаемый варианты, отменять и повторять действия | Исходник не меняется от правок; Reset отменяем; Undo/Redo работает в текущем открытии | Реализовано |
| R7 | Сохранять черновик и предотвращать тихую перезапись | После перезапуска черновик восстановлен; устаревшая revision получает 409 | Реализовано |
| R8 | Отделять черновик от явно переданного снимка | Apply сохраняет baseline/proposed/changes; поздние правки не меняют последний applied | Реализовано |
| R9 | Переносить только по поручению пользователя и проверять исходники | Тестовый Apply не меняет проект; агент сверяет sourceRevision, сохраняет логику и проверяет реальный экран | Протокол описан; перенос реальных тестовых правок не выполнялся |
| R10 | Давать переносимую интеграцию с агентами | Один макет и applied читаются через файлы/API из разных оболочек; инструкция не требует глобальной установки | Реализовано как инструкция; пакеты интеграции — следующий этап |
| R11 | Проверять критический сценарий редактора автоматически | Браузерные проверки покрывают drag, размеры, разделы, Apply и восстановление | Следующий этап |
| R12 | Делать состояние передачи понятным | Видно, передан ли текущий черновик, какой снимок передан и что делать дальше; отдельно отмечается тестовый режим | Реализовано в v0.2; автоматическая браузерная проверка остаётся отдельно |

## Поведение и состояния

Загрузка: дождаться серверной сессии; при ошибке показать причину и путь восстановления. Пустое дерево нельзя импортировать: документ должен иметь корень. При отсутствии правок показывается приглашение выбрать элемент. При отсутствии Apply `/api/applied` возвращает 404.

Редактирование: изменение валидируется до сохранения; некорректный ввод не становится документом. При конфликте сохранение прекращается; пользователь может экспортировать свой вариант и загрузить серверную версию. Импорт начинает новый baseline и очищает указатель applied. Предыдущие снимки остаются на диске.

Передача: снимок не равен выполненной задаче. Агент использует полное proposed-дерево; diff объясняет изменение, а не задаёт последовательность механических патчей. Новые черновые изменения требуют нового Apply перед переносом.

Доступность: стандартные поля и раскрываемые разделы доступны с клавиатуры; порядок меняется кнопками без drag. Дерево имеет role tree/treeitem; полноценная клавиатурная навигация дерева пока не реализована. Ошибки публикуются через область status.

## Ограничения и решения

- Локальный Node.js-сервер, файловое хранение, с dnd-kit/dom в браузере и локальной сборкой esbuild. По умолчанию loopback; публичная публикация не входит в задачу.
- UI — HTML/CSS/JavaScript. Дерево компонентов — промежуточное представление, а не AST Kotlin и не DOM приложения.
- Column/Card — вертикальные контейнеры, Row — горизонтальный, Box — наложение. Drag задаёт структуру, не абсолютные координаты.
- Представление не гарантирует точного совпадения с Android. Агент обязан пояснять приближения; callbacks, состояние, навигация и доступность сохраняются в исходном проекте.
- Допускается форматирование всего текста элемента. Выделение отдельных слов, произвольные координаты, универсальный парсер и облачная синхронизация вне текущего объёма.
- Одновременно редактировать одну сессию несколькими окнами нельзя; revision обнаруживает конфликт. Два процесса не должны использовать один каталог данных.

## Допущения и открытые вопросы

Для первого адаптера агент имеет доступ к файлам UI-проекта и может запустить локальный сервер. Браузер оболочки должен открывать localhost; поддержка конкретных версий Codex/Claude требует отдельной проверки, универсальность протокола не доказывает совместимость каждой оболочки.

Перед разработкой пакетов интеграции выбрать способ поставки: skill с инструкциями или MCP-инструменты. Не устанавливать глобальные пакеты автоматически. Вопрос свободного размещения решать отдельно: оно должно иметь корректное отображение в исходный UI-стек.

## Условие готовности следующего выпуска

R1–R12 проверены в своих границах; браузерный сценарий воспроизводим; подготовка и чтение передачи работают в двух выбранных оболочках агента. Один разрешённый перенос в реальный Android-проект собран и визуально проверен. Тестовые правки Mealio не служат разрешением на этот перенос.
