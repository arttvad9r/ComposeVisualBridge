# Спецификация Compose Visual Bridge

Статус: описание текущего прототипа и требований к следующему рабочему выпуску. Область: локальный редактор Android Compose-макетов и передача намерения агенту. Требования с пометкой «следующий этап» ещё не реализованы.

## Цель и сценарий

Дать пользователю возможность показать желаемые изменения интерфейса руками, без написания подробного текстового задания. Агент читает экран, готовит редактируемое представление, пользователь меняет его и передаёт снимок. Агент сопоставляет изменения с актуальным кодом, реализует их и проверяет настоящий экран.

Редактор запускается в браузере. Файлы и HTTP API обеспечивают совместимость с разными агентами. Первый адаптер — ручная подготовка JSON агентом для Jetpack Compose. Поддержка других UI-стеков возможна позже, но не является требованием первого выпуска.

| R13 | Свободно перемещать элементы прямо на макете | Элемент следует за мышью по X/Y; одна операция Undo, Esc отменяет; дерево сохраняется | Реализовано; проверено в Codex |

## Свободная и автоматическая компоновка — R15

По умолчанию редактор показывает свободный режим. Перед первой правкой фиксируется видимая геометрия всех узлов; размеры выбранного элемента больше не участвуют в расчёте соседей или его родителя. Resize контейнера сохраняет локальные позиции детей. Перемещение контейнера переносит его детей вместе с ним. Перекрытия и выход детей за границы возможны.

Переключатель «Компоновка» над макетом включает автоматический расчёт Row/Column/Box. Переход к автоматическому режиму снимает фиксацию геометрии; размеры и смещения сохраняются, поэтому позиции могут измениться. Возврат к свободному режиму фиксирует получившееся расположение. Переключение отменяется через Undo.

В свободном режиме точные размеры работают независимо; режимы «По содержимому», «Заполнить место», weight и выравнивание контейнера рассчитываются в автоматическом режиме. Изменение структуры через дерево, добавление и удаление намеренно пересчитывает компоновку; следующий жест снова фиксирует геометрию. Сохранение, экспорт и Apply содержат геометрию; перезагрузка её восстанавливает. Старые документы показываются без миграции до первой правки; baseline и старые applied не переписываются.

## Поведение и состояния

Загрузка: дождаться серверной сессии; при ошибке показать причину и путь восстановления. Пустое дерево нельзя импортировать: документ должен иметь корень. При отсутствии правок показывается приглашение выбрать элемент. При отсутствии Apply `/api/applied` возвращает 404.

Редактирование: изменение валидируется до сохранения; некорректный ввод не становится документом. При конфликте сохранение прекращается; пользователь может экспортировать свой вариант и загрузить серверную версию. Импорт начинает новый baseline и очищает указатель applied. Предыдущие снимки остаются на диске.

Передача: снимок не равен выполненной задаче. Агент использует полное proposed-дерево; diff объясняет изменение, а не задаёт последовательность механических патчей. Новые черновые изменения требуют нового Apply перед переносом.

Доступность: стандартные поля и раскрываемые разделы доступны с клавиатуры; порядок меняется кнопками без drag. Дерево имеет role tree/treeitem; полноценная клавиатурная навигация дерева пока не реализована. Ошибки публикуются через область status.

## Ограничения и решения

- Локальный Node.js-сервер, файловое хранение, с dnd-kit/dom в браузере и локальной сборкой esbuild. По умолчанию loopback; публичная публикация не входит в задачу.
- UI — HTML/CSS/JavaScript. Дерево компонентов — промежуточное представление, а не AST Kotlin и не DOM приложения.
- Column/Card — вертикальные контейнеры, Row — горизонтальный, Box — наложение. Drag в дереве меняет структуру; drag на макете изменяет визуальное смещение offsetX/offsetY в dp относительно позиции, заданной контейнером. Соседи сохраняют свои места; возможно перекрытие.
- Представление не гарантирует точного совпадения с Android. Агент обязан пояснять приближения; callbacks, состояние, навигация и доступность сохраняются в исходном проекте.
- Допускается форматирование всего текста элемента. Выделение отдельных слов, универсальный парсер и облачная синхронизация вне текущего объёма.
- Одновременно редактировать одну сессию несколькими окнами нельзя; revision обнаруживает конфликт. Два процесса не должны использовать один каталог данных.

## Допущения и открытые вопросы

Для первого адаптера агент имеет доступ к файлам UI-проекта и может запустить локальный сервер. Браузер оболочки должен открывать localhost; поддержка конкретных версий Codex/Claude требует отдельной проверки, универсальность протокола не доказывает совместимость каждой оболочки.

Перед разработкой пакетов интеграции выбрать способ поставки: skill с инструкциями или MCP-инструменты. Не устанавливать глобальные пакеты автоматически. Визуальные смещения передаются агенту как намерение размещения; при переносе он выбирает offset либо изменение компоновки и проверяет Android.

## Условие готовности следующего выпуска

R1–R15 проверены в своих границах; браузерный сценарий воспроизводим; подготовка и чтение передачи работают в двух выбранных оболочках агента. Один разрешённый перенос в реальный Android-проект собран и визуально проверен. Тестовые правки Mealio не служат разрешением на этот перенос.

## Проверка R13–R14 — 10 октября 2026

Отдельная сессия на 4181, данные data/gestures. В браузере Codex проверены движение вправо/вниз и вверх/влево, Esc, все восемь направлений resize, захват за верхний край вне средней ручки, минимальный размер с padding, Undo/Redo, восстановление после загрузки и тестовая передача дробного размера со смещениями. При масштабе 65% противоположные границы после resize сохранялись с погрешностью менее 0.05 CSS px. Погрешность округления до 0.1 dp допускается.

Перенос в Android не выполнялся. Поведение scroll/resize, изменение масштаба во время активного drag и touch/pen требуют дополнительных проверок.

## Проверка R15 — 10 октября 2026

В отдельной сессии data/free-layout на 4181 проверены восемь направлений resize кнопки при масштабе 65%: после первоначальной фиксации смещение соседей — 0 CSS px, ошибка противоположной границы менее 0.003 CSS px. Первоначальная фиксация округляет геометрию с погрешностью менее 0.02 CSS px в проверенном макете. Проверены resize вложенного Card без перемещения детей и соседней Card, Undo, Esc, free→auto→free, перезагрузка и тестовый Apply с геометрией и пояснением в отчёте. В автоматическом режиме увеличение высоты кнопки на 20 CSS px сдвинуло следующую Card на 20.018 CSS px. Координаты при восстановлении сравниваются относительно корня: сообщения редактора могут менять положение всего превью на странице.

11 Node-тестов проходят, включая валидацию геометрии/родителей, diff, историю, сброс кадров при переносе и сохранение frames в applied/API. Пользовательская сессия не использовалась для этих проверок. Перенос в Android не выполнялся.
