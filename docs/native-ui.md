# Настоящий Compose UI

Этот режим показывает настоящий PNG и рамки намерений. Перетаскивание здесь не меняет изображение элементов. Для живого редактирования используйте `edit-compose` по [инструкции](browser-compose.md). Нативный просмотр нужен как эталон и для инспекции.

Версия 0.7.0 открывает оригинальный Compose Preview в общей оболочке редактора: дерево и поиск слева, изображение и инструменты в центре, полный инспектор справа. Элементы выбираются по измеренным нативным bounds. Экран исполняется на Android через [Compose Buddy](https://github.com/mikepenz/compose-buddy), а браузер показывает его результат. Это устраняет реконструкцию интерфейса агентом. Изображение не меняется при сохранении пожелания: агент переносит намерение в Kotlin по поручению пользователя, затем новая сборка даёт новый кадр.

## Работа в редакторе

Текст, шрифт, размер, выравнивание, отступы, фон и структура задаются в инспекторе. Выравнивание доступно и при пожелании свободной компоновки. Перемещение и восемь ручек размера сохраняют намерения; рамка показывает желаемую геометрию, а настоящий PNG меняется после переноса в код и сборки. Изменение контейнера компенсирует смещения его непосредственных детей одной операцией Undo. Новые элементы обозначены как ожидающие переноса. Неизвестные исходные свойства остаются пустыми.

История до 100 операций сохраняется между открытиями. Черновик автоматически записывается; при конфликте или ошибке записи локальные правки сохраняются, а передача блокируется до разрешения проблемы. В сравнении показываются настоящий кадр перед последней передачей и кадр новой сборки той же сцены. Смена темы не подменяет исходник другой сценой. Экспорт содержит оригинальный захват. Подсказки открываются по небольшим значкам ⓘ рядом с соответствующим инструментом.

## Подготовка, сборка и запуск

Для Git-проекта с обычными Kotlin DSL plugins используйте готовые команды плагина. Они создают отдельную копию, добавляют debug runtime/KSP и Activity, затем компилятор находит оригинальные @Preview. Копия должна быть новым каталогом вне проекта; исходники и текущие сессии пользователя не меняются. Если существующих Preview нет, агент готовит небольшой каталог сцен, вызывающих оригинальные Composable с тестовыми аргументами, и передаёт его через --preview-source. Не нужно вручную перечислять функции в BuddyPreviewRegistryImpl.

```sh
node <plugin>/scripts/plugin.mjs prepare-native --project <Git root> --output <новая копия> --sdk <Android SDK> --upgrade-kotlin 2.3.20
node <plugin>/scripts/plugin.mjs native-build --workspace <копия>
node <plugin>/scripts/plugin.mjs native-catalog --workspace <копия>
node <plugin>/scripts/plugin.mjs create-native --project <Git root>
node <plugin>/scripts/plugin.mjs native-run --project <Git root> --workspace <копия> --serial emulator-5554 --state "Экран · светлая тема · тестовые данные" --preview <FQN из каталога>
```

Если нужны дополнительные сцены, добавьте `--preview-source <каталог Kotlin-файлов>` к prepare-native. Используйте каталог вне Android-проекта, чтобы не продублировать существующие объявления. Для другого application-модуля укажите `--module :feature:app`. SDK также можно задать через ANDROID_HOME при сборке. Из репозитория соответствующие команды: `node scripts/native-project.mjs prepare`, `build`, `catalog` с теми же параметрами.

Первый проверенный вариант: Kotlin/Compose compiler 2.3.20, KSP 2.3.6, Buddy 0.3.0, AGP 8.9.2, compileSdk 36, JDK 21. `--upgrade-kotlin` изменяет только копию; без него неподходящая версия отклоняется. KSP-процессор опубликован с Java class major=65, поэтому JDK 17 здесь недостаточно. Подготовка не поддерживает aliases/convention plugins, существующую KSP/Buddy-интеграцию, debug manifest, symlinks, flavors/splits и внешние Gradle-модули. Неподдерживаемый проект требует отдельного адаптера; основной build.gradle не переписывается. Готовый Android APK нельзя получить без Android toolchain.

Результат native-build/native-catalog — JSON с previews (реальные ключи для Activity), sourceRevision, apk и apkSha256. Используйте эти значения для установки APK и подключения ниже. Каталог появляется только после успешной сборки; правка исходников или замена APK блокируют чтение старого результата. Лог — bridge-native-build.log в копии. Пустой previews означает отсутствие обнаруженных @Preview, а не отсутствие экранов приложения.

В опубликованном Buddy KSP каталог состоит из функций; несколько @Preview-конфигураций одной функции не превращаются в несколько самостоятельных ключей. @PreviewParameter использует первое значение provider. Для независимо выбираемых сцен создавайте отдельные функции. Доступность private-функций, Preview providers и библиотечных составных аннотаций зависит от компилятора и Buddy: успешная сборка обязательна, одних сгенерированных файлов недостаточно. Автоматического создания состояния ViewModel/DI и извлечения всего UI пока нет.

## Что нужно подключить один раз

Node.js 22+ для соединения WebSocket; Android SDK, устройство или эмулятор и debug-интеграция Buddy. Архив плагина содержит редактор и адаптер протокола, но не Android SDK и зависимости Gradle. Точный список состояний приложения не извлекается автоматически: каталог содержит зарегистрированные Preview. Экран с ViewModel, DI или сетью должен иметь тестовую обёртку с воспроизводимыми данными, которая вызывает оригинальный Composable и тему.

Проверенный runtime: `debugImplementation("dev.mikepenz.composebuddy:compose-buddy-device:0.3.0")`. В тестовой копии Mealio потребовались Kotlin/Compose compiler 2.3.20 и compileSdk 36; опубликованный runtime подтянул Compose 1.10.6. Не обновляйте основной проект вслепую: проверьте зависимости и сборку в отдельной копии. JDK 17 и AGP 8.9.2 работали в этом опыте. Ручной registry был проверен в 0.4.0; в 0.5.0 также проверено обнаружение сцен через опубликованный KSP (см. выше).

Минимальный registry помещается в debug source set, пакет и имя класса должны совпадать с ожидаемыми Buddy. Не добавляйте его одновременно с KSP-генерацией такого же класса:

```kotlin
package dev.mikepenz.composebuddy.device

import androidx.compose.runtime.Composable
import dev.mikepenz.composebuddy.device.model.BuddyPreviewEntry
import dev.mikepenz.composebuddy.device.model.PreviewConfig

object BuddyPreviewRegistryImpl : BuddyPreviewRegistry {
    override val previews = mapOf(
        "bridge.Settings" to BuddyPreviewEntry(
            "bridge.Settings", "Настройки", listOf(PreviewConfig()),
            { config -> ProjectSettingsPreview(config) }
        )
    )
}

@Composable
private fun ProjectSettingsPreview(config: PreviewConfig) {
    // Здесь вызов оригинального экрана внутри его темы, с тестовыми
    // аргументами. Это единственная часть, специфичная для проекта.
    // Примените config.darkMode/fontScale и нужную локаль явно.
}
```

В debug-манифесте тестовой копии разрешите запуск через adb и уберите системные отступы, чтобы PNG и bounds имели начало (0, 0):

```xml
<manifest xmlns:android="http://schemas.android.com/apk/res/android"
          xmlns:tools="http://schemas.android.com/tools">
    <application>
        <activity android:name="dev.mikepenz.composebuddy.device.BuddyPreviewActivity"
                  android:exported="true"
                  android:theme="@android:style/Theme.Material.Light.NoActionBar.Fullscreen"
                  tools:replace="android:exported,android:theme" />
    </application>
</manifest>
```

Это настройка debug-стенда. Не переносите экспортированную Activity в release. Соберите и установите debug APK. Запустите сцену и пробросьте порт (замените SERIAL и PACKAGE фактическими значениями):

```sh
adb -s SERIAL shell am start -n PACKAGE/dev.mikepenz.composebuddy.device.BuddyPreviewActivity --es preview bridge.Settings --ei port 7890
adb -s SERIAL forward tcp:37890 tcp:7890
```

Buddy запускает сервер на устройстве; Bridge подключается только к loopback `ws://127.0.0.1:37890/`. Для другого стенда выбирайте свободный host-порт. `--source-revision` — реальный Git SHA при чистом дереве или SHA-256 детерминированного набора исходников и конфигурации сборки при изменениях. SHA должен соответствовать установленному APK; нельзя брать текущий HEAD, игнорируя локальные изменения.

## Открыть редактор

Из установленного плагина:

```sh
node <plugin>/scripts/plugin.mjs create-native --project <проект>
node <plugin>/scripts/plugin.mjs native --project <проект> --session <ID> --endpoint ws://127.0.0.1:37890/ --source-revision <SHA> --state "Настройки, ru, светлая тема, тестовый аккаунт, fontScale=1"
```

Используйте ID из первой команды. В ответе будет адрес страницы настоящего UI. Последующий `open` возобновляет сессию. Данные хранятся вне пакета, отдельно от других экранов. Для запуска из репозитория сначала `npm run build`, затем сервер с новым каталогом и свободным портом:

```sh
BRIDGE_DATA=/tmp/bridge-native-new PORT=4187 node server.mjs
node scripts/native.mjs connect --url http://127.0.0.1:4187 --endpoint ws://127.0.0.1:37890/ --source-revision <SHA> --state "Настройки, ru, светлая тема"
```

Откройте `http://127.0.0.1:4187/native`. Панель подключения содержит те же параметры; SHA требуется обязательно. При медленном старте Activity подключение повторяется до 10 секунд. После разрыва соединения или перезапуска сервера подключитесь явно; сохранённый кадр доступен без устройства.

## Работа с настоящим кадром

Выберите элемент на изображении или в дереве. Инспектор показывает текст, нативные свойства, bounds в dp и наличие подсказки исходника. Рамки масштабируются вместе с PNG; для сцены с системными inset задайте проверенные origin-x/origin-y в пикселях. Не подгоняйте позиции на глаз. Buddy не всегда сообщает file/line: в проверенном Mealio их не было. Агент должен найти соответствующий Kotlin и проверить подсказки перед переносом.

Сохраните нужные свойства как намерения: текст, размер шрифта в sp, цвет `#RRGGBB`/`#AARRGGBB`, размер в dp, смещение в dp или пояснение. Свободное перетаскивание, мгновенное изменение Android-изображения и клик по Android-кнопкам здесь пока не реализованы. Изображение остаётся исходным, поэтому пожелание не может быть принято за уже существующий результат.

Пользователь сверяет экран и отмечает подтверждение сцены. «Передать агенту» создаёт review-снимок с исходным PNG, деревом, SHA и намерениями; без подтверждения доступна тестовая передача. Агент читает его командой `read-native --project <проект> --session <ID>`. Снимок сам не разрешает менять исходники и не запускает агента. Сохранённая передача не меняется при дальнейших правках.

Если пришёл новый кадр при незавершённых намерениях, редактор оставляет исходный кадр и показывает ожидающее обновление. Чтобы перейти на новую сцену, сначала сохраните передачу, затем очистите черновик и обновите кадр. Обновление делает снимок текущего APK, без компиляции. После изменения Kotlin пересоберите/установите APK, запустите Preview и подключитесь с новым SHA; подтверждение нового кадра сбрасывается. Для другого Preview каталог использует его техническое имя как описание, которое следует сверить со сценой.

Можно импортировать сохранённый JSON-сообщение Buddy (`type: "frame"`) через `scripts/native.mjs import --url <URL> --input <JSON> --source-revision <SHA> --state <описание>`. Формат — PNG base64, dimensions, densityDpi и semantics; это не JSON макета. Обычный редактор продолжает работать независимо и требует только Node.js 20+.

Остановка: `node <plugin>/scripts/plugin.mjs stop --project <проект> --session <ID>`; данные остаются. Закройте собственную тестовую Activity и удалите только свой adb forward. Проверки и ограничения описаны в отчёте `docs/verification/native-preview-2026-10-11.md` репозитория.

## Найти выбранный элемент в Kotlin

В редакторе раскройте «Исходники экрана», укажите подготовленную рабочую копию после успешного `native-build` и нажмите «Найти в Kotlin». После выбора элемента инспектор покажет найденные места. Нажмите имя файла со строкой, чтобы прочитать фрагмент кода. Подключение исходников сбрасывает подтверждение сцены; с незавершёнными правками менять подключение нельзя.

Агент может передать `--workspace /absolute/copy` при `native`, либо подключить исходники уже полученного кадра:

```sh
node scripts/plugin.mjs source-native --project /absolute/project --session screen-ID --workspace /absolute/copy
# Для отдельного сервера:
node scripts/native.mjs source --url http://127.0.0.1:PORT --workspace /absolute/copy
```

Ревизия кадра должна совпадать с каталогом сборки. Поиск учитывает обычные и raw Kotlin-литералы, обращения `R.string.name` к простым строковым ресурсам и доступные runtime-подсказки. Комментарии и интерполированные строки не дают буквальных совпадений. Строки из состояния, составные/стилизованные ресурсы и вычисленные значения могут остаться неизвестными. Поиск охватывает рабочую копию, поэтому может найти неиспользуемый код или другой экран. Даже одно совпадение — кандидат; агент проверяет путь вызовов и конкретное свойство перед переносом. При нескольких совпадениях редактор показывает первые 12 и полное число найденных мест.

Файлы, строки, причины, фрагменты и ревизия сохраняются в неизменяемом native-снимке. Изменение входных файлов или APK блокирует новые намерения и передачу до получения кадра новой сборки; удалить черновик и прочитать старый снимок можно. Операции поиска и сохранения не изменяют Kotlin и не запускают перенос автоматически.

## Управление подключением и инструментами

`native-run` проверяет ревизию исходников и APK, устанавливает его только на указанный тестовый эмулятор, запускает Preview Activity, выделяет собственный ADB forward и возвращает `nativeUrl`. `--preview` можно опустить для первого элемента каталога. Запуск отклоняется при незавершённом черновике. Перезапуск Activity в начале запуска восстанавливает соединение в пределах десяти секунд. Команда `stop --project … --session …` останавливает сервер и удаляет только принадлежащий сессии forward. Эмулятор пользователя автоматически не выключается.

`setup` возвращает `native.nodeReady` и `native.buildReady`, найденные JDK и SDK. Для подключения нужен Node 22+, для сборки JDK 21+ и Android SDK. Приоритет Java: `BRIDGE_JAVA_HOME`, затем `JAVA_HOME`, затем отдельный JDK в `<BRIDGE_HOME>/toolchains/jdk-21.0.2`, затем PATH. SDK берётся из `--sdk`, Android-переменных окружения либо `~/Android/Sdk`. Локальный JDK не меняет системную Java и не входит в архив плагина. Несовместимость Gradle/Compose конкретного приложения нужно решать в отдельной копии; наличие редактора само по себе не гарантирует сборку любого проекта.
