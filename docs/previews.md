# Экраны проекта из Preview без эмулятора

Основной путь импорта экранов. Все `@Preview` модуля рисуются на компьютере (Robolectric + Roborazzi, JVM), каждый связанный экран открывается отдельной сессией в списке «Экран и состояние». Эмулятор, debug-APK и нажатия в приложении не нужны.

## Сценарий

1. Агент проверяет, что у нужных экранов есть `@Preview` с тестовыми данными. Если нет — добавляет их в проект пользователя (в рабочей ветке, не в `main`): вызов настоящего экрана в теме приложения с правдоподобными данными. Экраны с ViewModel вызываются через их stateless-вариант с параметрами.
2. Агент готовит адаптер со связями Kotlin-вызовов экранов (формат как у [live-адаптера](live-app.md#адаптер), `host` не обязателен).
3. Агент запускает:

```bash
node <пакет>/scripts/plugin.mjs edit-previews --project <проект> --adapter <адаптер.json> [--module :app]
```

Команда копирует проект в отдельный каталог, добавляет в копию тестовые зависимости и `integrations/android/BridgePreviewCapture.kt`, привязывает вызовы адаптера, выполняет `testDebugUnitTest` и восстанавливает исходники копии. Исходный проект не меняется.

4. Пользователь переключает экраны в списке, двигает элементы и нажимает «Передать агенту». Перенос в код — по общему протоколу, по поручению пользователя.

## Результат

JSON содержит `screens` (имя и сессия) и `skipped`: Preview, для которых нет связей в адаптере или кадр пустой, с причиной. Пропущенный экран не подменяется макетом: добавьте связи в адаптер и повторите команду.

## Требования и границы

- JDK 21, Android SDK, доступ к Maven Central при первой сборке (Robolectric скачивает android-all, около 150 МБ).
- В модуле явный `namespace` и Compose BOM (`compose-bom:` в `build.gradle.kts` или `composeBom` в `libs.versions.toml`).
- Версии зависимостей: `PREVIEW_TOOLCHAIN` в `previews.mjs` (Robolectric 4.16, Roborazzi 1.46.1, ComposablePreviewScanner 0.7.0); проверены с Kotlin 2.1, AGP 8.9, Compose BOM 2024.12.
- Устройство отрисовки: 411×891 dp, xxhdpi, SDK 35, светлая тема. Preview-аннотации с другими устройствами пока не учитываются.
- Кадр — отрисовка Preview с тестовыми данными, а не работающее приложение. Для реальных данных и навигации остаётся [live-путь](live-app.md).
- Цвет фона кнопок и других элементов берётся только из адаптера (`background`); без него макет показывает элемент без заливки.

Проверено на копии Subtrack 12 октября 2026: 4 Preview отрисованы за ~15 с, 3 экрана связаны (9–46 элементов), экран без связей в адаптере пропущен с причиной; переключение экранов в редакторе работает.
