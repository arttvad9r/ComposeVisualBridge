# Экраны проекта из Preview без эмулятора

Основной путь импорта экранов. Все `@Preview` модуля рисуются на компьютере (Robolectric + Roborazzi, JVM), каждый связанный экран открывается отдельной сессией в списке «Экран и состояние». Эмулятор, debug-APK и нажатия в приложении не нужны.

## Сценарий

1. Агент проверяет, что у нужных экранов есть `@Preview` с тестовыми данными. Если нет — добавляет их в проект пользователя (в рабочей ветке, не в `main`): вызов настоящего экрана в теме приложения с правдоподобными данными. Экраны с ViewModel вызываются через их stateless-вариант с параметрами. Это единственная ручная работа агента.
2. Агент запускает:

```bash
node <пакет>/scripts/plugin.mjs edit-previews --project <проект> [--module :app]
```

Учитываются и `private` Preview (так их создаёт Android Studio); если сканер не нашёл ни одного Preview, команда сообщает об этом, а не о сбое сборки. Карту связей с кодом строит `adapter.mjs` по исходникам, без агента: экраны — Composable-функции проекта, вызванные из `@Preview`; связываются вызовы `Text`, `Row`, `Column`, `Box`, `Surface`, `Scaffold`, `Card`, кнопки, чипы (`FilterChip`, `InputChip`, `AssistChip`, `SuggestionChip`), поля, `Switch`, `Icon`, `Image`, `Spacer` в экранах, вложенных функциях и построителях списков (`fun LazyListScope.section(...)`). Индикаторы прогресса, `Checkbox`, `RadioButton`, `Slider` и разделители показываются точным фрагментом отрисовки. Рамки (`border = BorderStroke(...)`, в том числе условные), скругления (`shape`, включая `CircleShape` и формы темы) и цвета неактивных кнопок вычисляются в самом приложении при отрисовке; пустое поле показывает свою подсказку, заполненное — подпись над значением (`label`); текст под полем (`supportingText`) и иконки внутри поля (`leadingIcon`, `trailingIcon`, фрагмент кадра) показываются как в приложении. Вызовы без скобок (`Column { ... }`) связываются. Если экран ветвится (`if (...) Box { ... } else Column { ... }`), корнем может быть любая ветка; в кадре должна быть отрисована одна. Кнопка без текста становится контейнером, содержимое кнопки с текстом не связывается отдельно. Цвета — явные аргументы (`color`, `containerColor`, `colors`, `.background(...)`, цвет подписи кнопки) или значения Material 3 по умолчанию. Повторяющиеся элементы различаются номером позиции в Compose (`bridgeSceneInstance`). Готовая карта сохраняется в копии: `<модуль>/build/compose-visual-bridge-adapter.json`. Собственный адаптер можно передать через `--adapter <JSON>` (формат [live-адаптера](live-app.md#адаптер), `host` не нужен).

Команда копирует проект в отдельный каталог, добавляет в копию тестовые зависимости и `integrations/android/BridgePreviewCapture.kt`, привязывает вызовы адаптера, выполняет `testDebugUnitTest` и восстанавливает исходники копии. Исходный проект не меняется.

3. Пользователь переключает экраны в списке и через «Дополнительно → Исходник не проверен» сравнивает исходный браузерный макет с кадром Preview: состав, текст, оформление и геометрию. Только после подтверждения совпадения (`verification.confirmedBy="user"`) правки передаются в режиме `review`. Без подтверждения доступен только `test`, который не разрешает перенос. Если макет неточен, сначала исправьте реконструкцию в отдельной сессии, сохранив прежний черновик. Перенос в код — по общему протоколу, по поручению пользователя.

Правки текста, который приходит из данных (`subscription.name`), относятся к тестовым данным Preview или к логике экрана — агент решает по смыслу и при сомнении спрашивает пользователя. После переноса агент повторно запускает `edit-previews` и сверяет новый кадр.

## Результат

JSON содержит `screens` (имя и сессия), `skipped` — Preview, которые не удалось связать или кадр пустой, с причиной, и `unbound` — функции, которые генератор не связал (например, содержимое кнопки). Пропущенный экран не подменяется макетом. Ненулевой код завершения Gradle прерывает весь импорт даже при наличии части готовых кадров; сообщение содержит код и путь к логу. Прежние сессии и latest не заменяются. Служебный `.bridge-previews.json` не входит в хеш исходников; ревизия возвращённых документов соответствует восстановленной рабочей копии.

В старых сессиях 0.10.0–0.10.6 могло сохраняться `confirmedBy="render"`. С 0.10.7 оно не считается подтверждением; исходные файлы сохраняются, но для переноса нужен новый снимок после сверки пользователем.

## Требования и границы

- JDK 21, Android SDK, доступ к Maven Central при первой сборке (Robolectric скачивает android-all, около 150 МБ).
- В модуле явный `namespace` и Compose BOM (`compose-bom:` в `build.gradle.kts` или `composeBom` в `libs.versions.toml`).
- Версии зависимостей: `PREVIEW_TOOLCHAIN` в `previews.mjs` (Robolectric 4.16, Roborazzi 1.46.1, ComposablePreviewScanner 0.7.0); проверены с Kotlin 2.1, AGP 8.9, Compose BOM 2024.12.
- Устройство отрисовки: 411×891 dp, xxhdpi, SDK 35, светлая тема. Preview-аннотации с другими устройствами пока не учитываются.
- Кадр — отрисовка Preview с тестовыми данными, а не работающее приложение. Для реальных данных и навигации остаётся [live-путь](live-app.md).
- Генератор не является компилятором Kotlin. Неизвестный вызов с заглавной буквы в UI-содержимом (например, `Canvas`, `AndroidView`, `AsyncImage`) или функция с неподдерживаемым телом-выражением останавливает автоматический импорт с файлом, именем функции и причиной. Проверяются также ветки и именованные content-слоты; обычные значения и обработчики событий не считаются UI. Анализ консервативный, не доказывает полноту произвольного Kotlin: сверка кадра обязательна и для собственного адаптера. Перегруженные функции и несколько устройств/тем Preview пока не поддерживаются. Иконки внутри поля редактируются только как часть поля.

Проверено на копии Subtrack 12 октября 2026: без ручного адаптера все 4 Preview отрисованы и связаны (~35 с с первой сборкой копии), значения полей, состояние переключателя и цвета кнопок совпадают с кадром; переключение экранов в редакторе работает. 13 октября 2026 на копии Mealio связаны все 8 Preview, включая экран с диалогом; поля с подписью, текстом под полем и иконкой совпадают с кадром.

Полный цикл проверен там же: правка текста и добавленная строка ушли агенту в режиме `review`, перенесены в код копии в ветке, повторный `edit-previews` показал результат.

Проверено на Mealio 13 октября 2026: 7 из 8 Preview связаны (RecipeDetail — несколько корней), содержимое карточек из `LazyListScope`-функций, рамки, круглые отметки, чипы настроек, подсказка пустого поля и неактивная кнопка совпадают с кадром.

14 октября 2026 на тестовом экране входа с `private` Preview: оба Preview связаны; надпись 32sp с высотой строки темы 24sp не обрезается после правки текста; добавление элемента после перетаскиваний не сдвигает остальные.
