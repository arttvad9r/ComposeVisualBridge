# Приёмка первого браузерного Compose-адаптера — 11 октября 2026

Проверена версия 0.8.0. Это проверяемый двусторонний адаптер ограниченного синтаксиса, а не приёмка всего продукта по B1–B7. Требования: [спецификация](../specs/browser-compose.md), остаток работ: [план](../plans/development.md).

## Что проверено

- Kotlin-вызовы получают разные стабильные ID даже при одинаковом тексте. В отдельную копию добавляются runtime-метки; отсутствующая/повторная связь и чужая сборка отклоняются. Измеренные цвета Material 3 получают через Compose, а не угадывают по PNG.
- Настоящий захват создаёт общий HTML-редактор, исходный Android-кадр хранится как эталон. Create-compose не подтверждает соответствие за пользователя.
- Playwright двигает сам HTML-элемент, проверяет положение относительно родителя, Undo, ширину после resize и видимый размер шрифта. Связь с Kotlin сохраняется. Это отдельный тест от нативных рамок поверх PNG.
- План читает неизменяемую подтверждённую передачу. Поздний черновик не меняет перенос. План сам ничего не пишет. Apply допускает только отдельную подготовленную копию и повторно проверяет файл/ревизию всех исходников.
- Повторное инструментирование/восстановление сохраняет исходник и работает после нового импорта перенесённых правок. Чужой служебный файл не перезаписывается. Ресурсные выражения и callbacks сохраняются; правка ресурсного текста требует разрешения агентом.
- Смена порядка/родителя, добавление элементов и новый экран имеют Kotlin-представление. Свободная компоновка переносится в Box с измеренными размерами и позициями; scope-weight не остаётся вне Row/Column. Неподдерживаемые свойства не игнорируются молча.

## Настоящий Android-цикл

Исходный BridgeTest оставался неизменным. Рабочая копия — `/tmp/cvb-browser-compose/workspace`, отдельный API 36 эмулятор `emulator-5584`, 720×1280, density 320. JDK 21 используется по частному пути; системная Java не менялась. Тестовые серверы используют отдельные каталоги и свободные порты; эмулятор и соединения после проверки остановлены.

1. Импорт TestScreen → инструментирование → сборка → новый настоящий захват LightPreview. Связано 9 элементов редактора с точными исходными вызовами.
2. Restore вернул исходную ревизию всей рабочей копии. Управляемый create-compose сохранил Android-эталон и оставил verification пустым.
3. В Chromium текст реально перемещён на 20/10 dp, Undo восстановил его. Для переноса заданы 18 sp вместо 14 sp и смещение 20/10 dp; добавлен Text «Новый элемент».
4. План применён только к тестовой копии. Из того же документа создан CreatedScreen.kt. Debug APK успешно собран с обоими экранами.
5. Новый Android-кадр содержит 18 sp и добавленный текст. Созданный экран скомпилирован; его навигация не подключалась. Код генератора установленного плагина совпадает с кодом скомпилированного нового экрана.

## Визуальные расхождения

Оба снимка имеют 720×1280. Для исходной сцены доля пикселей с RGB-разницей >24 — 1.13%, RMSE 0.0566. Для результата — 1.43%, RMSE 0.0673. Пустой фон снижает общую долю: в отдельных исходных текстовых областях расхождения доходят до 16.3%. Поэтому эти цифры не являются автоматическим подтверждением точности.

Исправлены обрезка по Card, лишняя браузерная тень и вертикальные метрики текста. Остаются различия растеризации/позиционирования шрифта. Масштабирование текстовой высоты после изменения fontSize — приближение на основе захваченных метрик, а не гарантированное измерение Android. Передача обычной сессии требует сравнения и подтверждения пользователя. Подтверждение в протокольном тесте синтетического фикстура не является подтверждением пользовательского экрана.
