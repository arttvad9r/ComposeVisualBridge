## Подтверждённые проблемы

### A1 · P1 · HTTP API тихо повреждает UTF-8

**Место:** `server.mjs:44–47`, функция `body`.

Каждый Buffer из HTTP-потока отдельно преобразуется в строку через `text += chunk`. Граница сетевого chunk может пройти внутри многобайтового символа. На обеих половинах возникает символ замены; JSON остаётся синтаксически корректным и сохраняется без ошибки. Затронуты обычные и native API, которые используют общий `body`.

**Воспроизведение:** PUT `/api/draft` с названием `Тест`, отправленный двумя частями с паузой 80 мс и разрывом после первого байта `Т`. Ответ HTTP 200, сохранённое название — `��ест`.

**Исправление:** считать лимит по байтам Buffer, объединять Buffer перед единственным UTF-8 декодированием либо использовать потоковый StringDecoder. Проверить также разрыв внутри emoji и отказ при превышении лимита.

### A2 · P1 · Импорт теряет последнюю несохранённую правку

**Место:** `public/app.mjs:578–585`, обработчик импорта; архивация в `server.mjs:96–108`.

Импорт очищает 500-мс таймер автосохранения и ждёт уже существующую очередь, но не добавляет актуальный документ в очередь. Сервер архивирует свою прежнюю версию. Затем браузер заменяет историю и локальный cache импортированным документом. Утраченная правка отсутствует и в черновике, и в доступном архиве.

**Воспроизведение:** в Chromium изменить текст `Исходный` на `Несохранённый` и сразу импортировать другой валидный JSON. Импорт успешен; `previousSession/session.json` содержит `Исходный`.

**Исправление:** перед заменой дождаться успешного сохранения актуального документа либо явно архивировать локальный документ. При ошибке или конфликте сохранения остановить импорт, оставив правки доступными. Проверить импорт сразу после ввода и после отказа записи.

### A3 · P1 · Частичная запись инструментирования уничтожает восстановление

**Место:** `scene.mjs:63`, `instrumentScene`; аналогичная небезопасная запись в `compose.mjs:168–169`, `instrumentWorkspace`.

Инструментирование пишет прямо в существующий Kotlin-файл. `writeFile` может сначала обрезать файл и записать часть содержимого, а затем вернуть ошибку. В `instrumentScene` файл попадает в список rollback только после успешной записи. На ошибке текущий частично записанный файл не восстанавливается, а новый manifest с оригиналом удаляется. В `instrumentWorkspace` catch также удаляет новый manifest без восстановления повреждённого target.

**Воспроизведение:** отдельная временная копия, подмена `fs/promises.writeFile` только для target: записать первые 10 символов, затем бросить `ENOSPC`. `instrumentScene` вернул ошибку; файл стал `package te`, `.bridge-scene-import.json` отсутствует. Оригинальный внешний проект в этом эксперименте не участвовал.

**Исправление:** готовить содержимое во временных файлах и заменять target атомарно; сохранять recovery manifest до гарантированного завершения/восстановления. Для нескольких файлов обеспечить восстановимый прогресс операции. Нужны проверки частичной записи, отказа rollback и аварийного завершения между файлами.

### A4 · P1 · Kotlin-перенос складывает отступы вместо замены оси

**Место:** `compose.mjs:81`; сравнить renderer `public/app.mjs:241–243`.

В HTML `paddingHorizontal` заменяет левую и правую составляющие общего `padding`. Kotlin-патч добавляет два последовательных `Modifier.padding`, которые складываются.

**Воспроизведение:** исходный `Modifier.padding(16.dp)`, добавить в документ `paddingHorizontal: 8`. Редактор задаёт горизонталь 8 и вертикаль 16. Патч выдаёт `Modifier.padding(16.dp).padding(horizontal = 8.dp, vertical = 0.dp)`: горизонталь становится 24.

**Исправление:** согласовать каноническую модель осей и генерировать один эквивалентный padding, учитывая порядок исходной цепочки. Проверить сочетания общего отступа с каждой осью и их удаление. Текст патча воспроизведён; новый Android-кадр в этом аудите не снимался.

### A5 · P1 · Изменение размера переставляет Modifier относительно padding

**Место:** `compose.mjs:77–80`, `modifierChanges`.

Изменённый Modifier удаляется со своего места и дописывается в конец цепочки. Порядок модификаторов Compose влияет на constraints и геометрию, поэтому это меняет также смысл неизменённых свойств.

**Воспроизведение:** для `Box(Modifier.width(100.dp).padding(16.dp))` изменить только `width` на 120. Патч выдаёт `Modifier.padding(16.dp).width(120.dp)`, а не сохраняет порядок `width → padding`. Это способно дать внешнюю ширину с дополнительными отступами вместо заданной ширины.

**Исправление:** заменять аргумент существующего вызова на месте; при удалении/добавлении и связанных модификаторах проверять семантику цепочки либо требовать переноса агентом. Добавить нативную проверку размеров до/после; текущая проверка подтвердила перестановку в сгенерированном исходнике.

### A6 · P2 · Сброс enabled не переносится в Button

**Место:** `compose.mjs:109`.

Для существующей кнопки аргумент `enabled` записывается только при определённом новом значении. Если свойство удалено из документа, старый аргумент не удаляется.

**Воспроизведение:** импортировать `Button(onClick = {}, enabled = false) { Text("x") }`, удалить `props.enabled` из текущего документа, вызвать `composePatch`. Патч сохраняет `enabled = false`, повторный импорт получает `false` вместо возврата к значению по умолчанию.

**Исправление:** при сбросе удалять аргумент из argumentsMap. Проверить false/true/default через patch и повторный импорт.

### A7 · P2 · Полный Node-набор сейчас не проходит

**Место:** `tests/scene.test.mjs:31`, тест `Runtime typography defaults to normal instead of inheriting bold; native PNG assets preserve pixels`.

Тест создаёт Image-документ через `{...doc, root: ...}`, оставляя `doc.layout.frames` от прежнего дерева. Валидатор правильно отклоняет ссылки на отсутствующие ID: `layout.frames: ID, родитель и геометрия должны соответствовать дереву`.

**Исправление:** построить независимый Image-документ с согласованным layout. Это ошибка тестовых данных, а не подтверждение дефекта PNG renderer, но `npm test` сейчас возвращает ненулевой код и приёмка выпуска не пройдена.

### A8 · P2 · Native показывает сохранение после ошибки операции

**Место:** `public/native.mjs:121`, `mutate`.

Catch ставит `Ошибка операции`, но finally безусловно заменяет её на `Черновик сохранён ✓`, если нет pending. Пользователь одновременно видит ошибку операции и успешный статус.

**Воспроизведение:** Chromium, загруженный native-кадр; перехват POST `/api/native/confirm` с ответом HTTP 500. Notice содержит `injected write failure`, saveStatus — `Черновик сохранён ✓`.

**Исправление:** хранить результат операции и обновлять статус успеха только после успешного ответа. Проверить отказ confirm/apply/history отдельно от отказа draft.

## Архитектура, безопасность и готовность

- Сервер привязан к loopback, проверяет Host/Origin, отдаёт статические файлы по явному allowlist, использует CSP и nosniff. Buddy URL ограничен loopback. Это полезные границы локального продукта; удалённое размещение с аутентификацией не проверялось.
- HTTP мутации сериализованы, revision защищает от тихой конкурентной перезаписи. Основной JSON сохраняется через temp+rename; failed apply очищает недописанный снимок. Это не распространяется на прямую запись Kotlin при инструментировании — A3.
- Передача готовит отдельный снимок. Автоматического изменения внешнего UI-проекта из Apply не обнаружено. Подтверждение исходного макета связано с fingerprint, эталоном и версией Bridge; native source mapping явно остаётся набором кандидатов.
- Исходники и APK проверяются по ревизии/хешу; копирование проекта исключает ряд секретов, запрещает symlink и вложенную рабочую копию. Это не универсальный сканер секретов и не изоляция выполнения Gradle чужого проекта.
- В коде много длинных однострочных функций, особенно в importer, scene и native editor. Это усложняет проверку rollback, порядка операций и согласованности модели. Устранение A3–A5 полезно сопровождать выделением небольших именованных операций, без смены стека.
- Приёмка B2/B6/B7 и цикл фиксации результата переноса остаются открытыми в планах. Универсальный Kotlin, каталог всех состояний, навигация по работающему приложению и второй реальный проект не подтверждены этим аудитом. Пройденные Chromium-сценарии не закрывают эти требования.
- Документация требует синхронизации: README сообщает версию 0.8.1, но раздел установки и `docs/plugin.md` указывают пакет 0.7.0; в основной спецификации остаётся статус 0.3.0 и старые количества проверок. Node 20 достаточен для базового редактора, но native WebSocket-путь требует Node 22+; требование должно быть ясно на основном пути запуска.

4. Синхронизировать документацию, собрать пакет и пройти установленным пакетом две последовательные итерации на отдельном Android-проекте. После этого оценивать закрытие открытых пунктов планов.
