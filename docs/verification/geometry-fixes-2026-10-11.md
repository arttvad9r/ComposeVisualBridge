# Исправление геометрии Compose — 0.8.2

Исправлены три расхождения [предыдущего Android-прогона](android-geometry-2026-10-11.md): внешний размер при `padding → width/height`, заполнение дочернего Text в Box и область background после padding. Это проверка ограниченного автоматического режима; полная приёмка реального проекта остаётся открытой.

## Изменения

- Новый импорт хранит `compose.modifierModel="outer-size-v1"` и порядок групп Modifier в каждой привязке. Общая модель используется importer, renderer и Kotlin-адаптером, включена в переносимый пакет.
- Числовые width/height означают внешние размеры. При `.padding(16.dp).width(100.dp).height(32.dp)` импорт получает 132×64 dp. Внешняя ширина 120 dp переносится как width(88.dp), 140 dp — как width(108.dp), без перестановки Modifier. Правка padding сохраняет числовой внешний размер.
- Box имеет явные grid-треки, поэтому заполняющий Text занимает доступное содержимое. Background после padding рисуется во внутренней области, перед padding — во внешней.
- Валидатор проверяет маркер и порядок. Повторяющиеся padding требуют адаптера; отрицательный размер после вычитания внешних отступов отклоняется. Свободное преобразование контейнера с внутренним фоном отклоняется вместо расширения области заливки.
- Старые сессии и неизменяемые снимки читаются без переписывания. Для автоматического переноса изменённого старого Compose-импорта нужен повторный импорт в отдельную сессию с сохранением прежнего черновика.

## Проверки

- `npm test`: 67/67, без пропусков, после последних изменений и сборки пакета 0.8.2. Проверены порядок, внешний размер, изменение осей, повторный импорт, отказ неоднозначного переноса и старые документы.
- `npm run test:browser`: 54/54 Chromium-сценария. Новый тест проверяет четыре случая настоящего стенда, поля размеров/отступов, заполнение Box, drag resize, Undo/Redo, reload, тестовый Apply, Kotlin-план и пиксели внутреннего фона. После полного набора renderer не менялся.
- `tests/android/replay-geometry.mjs`: новый renderer сравнён с тремя сохранёнными настоящими Android-кадрами предыдущего прогона. Хеш Kotlin сверяется с исходным импортом, ревизия кадра — с успешной сборкой. У всех четырёх случаев совпали x/y/width/height внешнего контейнера и дочернего Text с допуском менее 0.5 dp; выбранные пиксели фона совпали точно. `visualMatches=true`, `freshAndroidBuild=false`.
- Две новые последовательные правки 120/140 dp перенесены в Kotlin отдельной копии и успешно прошли настоящую `:app:compileDebugKotlin`, включая инструментирование runtime-метками и восстановление исходников после каждой компиляции. Это компиляция нового кода, без сборки/установки нового APK и без нового кадра. Планы и журналы: `/tmp/cvb-geometry-kotlin-20261011`; JDK 21 и существующий Android SDK, пользовательские исходники не использовались.
- `node --check` изменённых модулей и `git diff --check`: без ошибок.

Повторное сравнение использует исходники уже собранных кадров: B имеет внешнюю ширину 132/152/172 dp. Оно доказывает исправление renderer для этих реальных сцен, но не заменяет новый Android-захват после задания внешних 120/140 dp. Правильность новых Kotlin-чисел и повторного импорта проверена отдельно Node/Chromium-тестами; оба новых варианта Kotlin скомпилированы.

## Первая попытка новой Android-приёмки

Первоначально свежий стенд пытался запуститься в новой копии с отдельным AVD на 5586. После смены окружения `/dev/kvm` стал недоступен, включая запуск с повышенными правами. Программный режим `BRIDGE_TEST_ACCEL=off` сообщал о зависших QEMU-потоках и не загрузился; попытка остановлена. На этом этапе новая нативная приёмка оставалась открытой. Позже пользователь запустил OnePlus 13s на хосте; результат нового прогона приведён ниже.

Артефакты повторного сравнения: `/tmp/cvb-geometry-replay-20261011` (evidence и новые Chromium PNG); настоящие исходные кадры: `/tmp/cvb-audit-geometry-final-20261011`. Пакет: `dist/compose-visual-bridge-0.8.2.tgz`. Все тестовые сессии отдельные; пользовательская сессия и основной Mealio не изменялись. Плагин собран, установка в пользовательское окружение не выполнялась.

Для повторной нативной приёмки на машине с KVM:

```sh
node tests/android/geometry.mjs --template /tmp/cvb-browser-compose/workspace --output /tmp/cvb-geometry-new-run --sdk $ANDROID_HOME --port 5586
```

Стенд теперь требует совпадения внешних/внутренних размеров и отступов, а также проверяет выбранные пиксели области заливки. Различия растеризации текста, clipping/radius/border в произвольных цепочках и другие viewport/fontScale этим прогоном не закрыты.

## Новая Android-приёмка на OnePlus 13s

Пользователь запустил тестовый `emulator-5584` с AVD oneplus-13s-1, Android API 37. Стенд получил три новых APK/настоящих кадра: исходник и две последовательные итерации. Использованы новая копия подготовленного минимального проекта, отдельные BRIDGE_DATA/порты и отдельное приложение `dev.composevisualbridge.geometry`.

Экран на время сравнения приведён к 720×1280 px, density 320 (360×640 dp). После проверки восстановлены исходные 1216×2640 px и density 560; эмулятор оставлен работающим. Новая опция `--serial` использует явно выбранный внешний тестовый эмулятор и не запускает второй AVD. Debug-подпись создана отдельно в `/tmp/cvb-geometry-android-home-20261011`.

| Случай | До: внешний / внутренний размер, dp | Первая правка | Вторая правка |
|---|---|---|---|
| A: width/height перед padding | 100×64 / 68×32 | 120×64 / 88×32 | 140×64 / 108×32 |
| B: padding перед width/height | 132×64 / 100×32 | 120×64 / 88×32 | 140×64 / 108×32 |
| C: общий padding, переопределение осей | 100×64 / 68×32 | 100×64 / 84×32; H=8, V=16 | 100×64 / 84×64; H=8, V=0 |
| D: padding по осям, сброс H | 100×64 / 84×32 | 100×64 / 100×32; H=0, V=16 | 100×64 / 100×32; H=0, V=16 |

Все нативные assertions прошли; расхождений браузерных и нативных размеров/отступов нет: `visualMatches=true`, `visualDifferences=[]`. 15 проверок пикселей подтверждают цвет внутренней области и белые внешние отступы после переноса. Ошибок JavaScript нет. Источник восстановлен после каждого захвата, подготовленный шаблон не изменён, применённые снимки неизменны. `npm test` повторно: 67/67. Полный набор 54 Chromium-сценариев прошёл ранее на той же версии renderer; в этом этапе изменён только Android-стенд и документация.

Первый успешный свежий прогон: `/tmp/cvb-geometry-oneplus-20261011`. Итоговый прогон после добавления явной проверки x/y контейнеров и дочерних Text: `/tmp/cvb-geometry-oneplus-final-20261011`, также без расхождений. Итоговый evidence содержит 64 сравнения координат/размеров и 16 сравнений отступов в двух итерациях; отдельно прошли 15 проверок пикселей Android/HTML. В каталогах сохранены снимки, capture/import JSON, планы Kotlin и каталоги APK с SHA. Для воспроизведения на уже запущенном тестовом эмуляторе:

```sh
ANDROID_USER_HOME=/tmp/cvb-geometry-android-home-20261011 node tests/android/geometry.mjs --template /tmp/cvb-browser-compose/workspace --output /tmp/cvb-geometry-next-run --sdk $ANDROID_HOME --serial emulator-5584
```

Три обнаруженные проблемы автоматического режима подтверждены новой нативной приёмкой. Это не полная приёмка Mealio: темы, ресурсы/callbacks, длинные строки, повышенный fontScale и адаптивность реального экрана остаются в плане шага 3.
