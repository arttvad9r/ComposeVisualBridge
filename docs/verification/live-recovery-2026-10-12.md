# Проверки восстановления live-захвата — 0.9.1

В 0.9.1 исправлены восстановление host при раннем отказе подготовки и проверка свежести кадра при разных часах Android и хоста. Первый запуск host-стенда обнаружил ошибку адаптера Button; она исправлена, новый APK собран. Шаги 5–6 [плана готовности](../plans/development.md) остаются открытыми до повторной проверки.

## Исправления

Оболочка host теперь восстанавливается после ошибки до инструментирования сцены, после ошибки сборки и после успешной подготовки. Параллельное изменение host сохраняется и даёт конкретную ошибку. При одновременном отказе подготовки и восстановления выводятся обе причины.

Новый captureProtocol=2 использует launchId. Перед запуском Activity live-run создаёт приватный files, удаляет прежний кадр и записывает токен запуска; Kotlin helper добавляет его в кадр. edit-live проверяет совпадение токена, sourceRevision и SHA APK. Время остаётся диагностикой. Для запуска прежнего APK нужна новая prepare-live; сохранённые сессии остаются совместимыми. Контексты старых захватов без launchId читаются с прежней проверкой времени.

## Нативная проверка с хоста

Пользователь подтвердил доступный на хосте `/dev/kvm` с правами `crw-rw-rw-`, major/minor 10:232. В обычной и расширенной среде агента путь отсутствует. Изменение прав на хосте не исправило видимость устройства в среде. Поэтому приёмка Android не объявляется успешной.

Подготовлен `tests/android/subtrack-live.mjs`, запускаемый пользователем в обычном терминале хоста. Он проверяет KVM до аренды, принимает только свободный AVD через android-emu, задаёт serial во всех adb-командах и освобождает свою аренду в finally. Старую занятую аренду oneplus-13s-1 не использует. Процесс стенда указан владельцем аренды через EMU_OWNER_PID.

Стенд использует только тестовую debug-копию и отдельный BRIDGE_HOME: пустой светлый список → две одинаково названные подписки → список → детали → тёмный список. Проверяет разные runtime ID одинаковых строк и сохранение связей после смены темы, повторное открытие captureId, поздний браузерный черновик, переключение экранов и stop/open с историей Undo. При изменившейся форме или неоднозначной UI-цели останавливается. PNG Android и редактора сохраняются для отдельной визуальной сверки. Его unit-тесты подтверждают только разбор XML и отказ при неоднозначности. Первый настоящий запуск и исправление описаны ниже.

```sh
cd <ComposeVisualBridge checkout>
node tests/android/subtrack-live.mjs \
  --workspace /tmp/cvb-subtrack-live-launch-id-20261012 \
  --output /tmp/cvb-subtrack-host-check-20261012
```

Каталог output должен быть новым. `evidence.json` содержит результаты и ошибки очистки; при успешном сценарии visualAccepted всё равно остаётся false до визуальной сверки кадров. Серверы стенда останавливаются, данные и кадры остаются в output. Приёмка model turn и автоматического onboarding Codex также остаётся открытой, как указано в [отчёте 0.9.0](screens-plugin-2026-10-12.md).

## Ошибка первого host-запуска и исправление Button

Пользователь запустил стенд на хосте. Собственная аренда oneplus-13s-2 загрузилась как emulator-5554; APK установлен, настоящий захват получен. Импорт остановился на пустом экране: `Вложенная привязка внутри листа: rb271f096bfbd7e40fbc9dc99`. Этот ID соответствует `/EmptySubscriptions-Button-0/`. Адаптер исключал Text внутри Button, но оставлял Icon и Spacer. Модель Button представляет весь вызов одним узлом и не допускает независимых дочерних связей.

Evidence первого запуска: `/tmp/cvb-subtrack-host-check-20261012/evidence.json`, captures пуст, nativeScenarioPassed=false, visualAccepted=false, cleanupErrors пуст. Аренда освобождена. Это подтверждает запуск Android и отказ импорта, но не переходы или темы. Сырой кадр при этом запуске не сохранялся до bind, поэтому PNG для визуальной приёмки отсутствует.

Исправленный адаптер удаляет четыре внутренние связи: Icon/Spacer в Button функций SubscriptionListScreen и EmptySubscriptions; остаётся 70 правил. Иконки и интервалы сохранены в настоящем Kotlin и APK, весь Button остаётся одним узлом импортируемого дерева. prepareScene теперь до инструментирования отклоняет явно вложенную связь внутри листа в том же Kotlin-вызове с указанием обоих ключей. Проверка runtime-дерева остаётся обязательной для связей через отдельные функции и scopes.

Регрессионный тест проверил отказ для Icon, Spacer и Text внутри Button без записи манифеста и изменения источника; корректная одна связь Button сохраняет содержимое и callback измерения текста. **npm test: 83/83**, затронутые Chromium-сценарии scene/project: **2/2**, node --check и git diff --check прошли. Предыдущие 57/57 и установленный сценарий 1/1 относятся к состоянию до этой дополнительной защиты. Архив рабочего пакета пересобран через pretest; установленный временный cache после этого исправления не обновлялся.

Новый APK: `/tmp/cvb-subtrack-live-leaf-fix-20261012`, SHA-256 `ac6fbb06655e969bb1d6d1eb6a34c8237c3ff795eded05edfac597f5e8190ae8`; assembleDebug прошёл за 45 секунд. Исходники оригинального Subtrack и восстановленной копии сверены с хешами адаптера. Evidence: `/tmp/cvb-live-leaf-fix-build-evidence-20261012.json`. Логи: `/tmp/cvb-live-leaf-fix-build-20261012.log`, `/tmp/cvb-live-leaf-fix-node-20261012.log`, `/tmp/cvb-live-leaf-fix-browser-20261012.log`.

Теперь стенд сохраняет raw JSON и PNG при отказе bind, чтобы не терять диагностику после освобождения устройства. Повторный запуск использует новую копию и отдельный каталог, оставляя первый результат нетронутым:

```sh
cd <ComposeVisualBridge checkout>
node tests/android/subtrack-live.mjs \
  --workspace /tmp/cvb-subtrack-live-leaf-fix-20261012 \
  --output /tmp/cvb-subtrack-host-check-retry-20261012
```

## Доступ к KVM после изменения разрешений

После изменения пользователем разрешений обычная команда всё ещё не видит /dev/kvm, но расширенный запуск `emulator -accel-check` вернул код 0: `KVM (version 12) is installed and usable.` Блокер KVM для выполнения с расширенными правами снят.

Агент запустил исправленный стенд вне sandbox на свободном oneplus-15 через android-emu. Эмулятор загрузился как emulator-5556, live-run установил APK и открыл Subtrack. Проверка остановилась на захвате пустого списка: приватный файл files/compose-visual-bridge-live.json не появился после нажатия кнопки стендом. Причина требует отдельной проверки нажатия и Kotlin helper; прежняя ошибка вложенной связи в этом запуске не воспроизведена и не считается нативно принятой.

Evidence: `/tmp/cvb-subtrack-agent-check-20261012/evidence.json`, nativeScenarioPassed=false, visualAccepted=false, cleanupErrors пуст. Собственная аренда освобождена; android-emu status подтвердил oneplus-15 free. Шаги 5–6 остаются открытыми из-за незавершённого захвата, а не отсутствия KVM вне sandbox.
