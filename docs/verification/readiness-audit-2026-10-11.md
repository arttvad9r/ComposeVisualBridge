# Аудит готовности к реальным проектам — 11 октября 2026

Это состояние до исправлений первого этапа. Потеря известного семейства шрифта, перенос подчёркивания/прокрутки/stretch и общая матрица передачи затем исправлены: [результат этапа 1](readiness-step1-2026-10-11.md). Остальные ограничения ниже сохраняются.

## Вывод

Compose Visual Bridge уже содержит работающий редактор, локальный сервер, сохранение и протокол передачи, установленный плагин и ограниченный двусторонний Compose-адаптер. Это больше, чем набор инструкций. Однако готовность к произвольному реальному Android-проекту не подтверждена. Контролируемые проверки на отдельных копиях можно продолжать сейчас; обычный рабочий процесс требует устранения перечисленных ниже пробелов.

Проверены исходники редактора, модель/валидатор, сервер, Kotlin-адаптер, запуск/подготовка Android, CLI, упаковка, инструкции двух навыков и документы приёмки. Проверка не изменяла пользовательскую сессию и внешние Android-исходники. Новая Android-сборка в этом аудите не выполнялась; прежняя нативная приёмка взята из проектного отчёта, а не повторена.

Свежий прогон: `npm test` — **46/46**, `npm run test:browser` — **47/47**. Setup установленного 0.8.1 возвращает готовность редактора и доступные Node 26, JDK 21, SDK. Эти результаты подтверждают покрытые сценарии, а не универсальность импорта или точность нативного результата.

## Подтверждённые проблемы и недостающие функции

### 1. Достоверность исходного экрана — обязательна до рабочего переноса

`compose.mjs:bindCapture` принудительно устанавливает `fontFamily='Roboto'`. Чистая проверка parse → bind с синтетическим кадром воспроизвела **Serif → Roboto**. Это потеря известного свойства, а не только отличие растеризации. Проектные шрифты, типографика темы и полная палитра Material не извлекаются как единый контракт.

Прежний [нативный цикл](browser-compose-2026-10-11.md) обнаружил значимые локальные различия текста; размер после смены шрифта/кегля частично вычисляется приближённо. Стандартные браузерные Serif/Monospace/Cursive могут отличаться от Android. Нужны измерения и контроль по областям элементов, а не только малая средняя ошибка всего кадра.

В `index.html` обычное «До» — исходный HTML-макет; настоящий кадр доступен через сравнение исходника. Не следует выдавать это «До» за доказательство Android-соответствия. Несоответствие должно быть диагностировано до переноса, отдельно от пользовательского diff. Проверку можно поручить агенту, не возвращая техническую анкету пользователю.

### 2. Возможности UI и переноса расходятся — обязательна согласованная матрица

Чистые вызовы текущего генератора/патчера подтвердили:

| Доступно в редакторе | Текущий Kotlin-адаптер |
| --- | --- |
| TextField, Switch, Icon, Image | Нет адаптера компонента |
| Подчёркивание текста | `Нет переноса свойства textDecoration` |
| Прокрутка контейнера | `Нет переноса свойства scrollable` |
| Растягивание детей | `stretch требует модификаторов дочерних элементов` |
| Roboto Flex | Требуется ресурсный адаптер |

Агент может переносить такие намерения вручную; снимок их сохраняет. Но текущий автоматический Compose-путь их не поддерживает, и ошибка обнаруживается поздно. Нужен общий реестр: поддерживается напрямую / требует работы агента / ещё недоступно. Ошибка не должна впервые всплывать после редактирования и передачи. Свойства нового компонента тоже должны иметь определённый перенос.

### 3. Обычная структура Android-проектов не покрыта

`scripts/native-project.mjs:prepare` требует корень Git-проекта, Kotlin DSL, явные plugin id и версии Kotlin в корневом файле. Version catalog/alias и распространённые существующие KSP-интеграции не покрыты; при KSP/Buddy команда отклоняет проект. Подготовка привязана к проверенным версиям Buddy/KSP/Kotlin; edit-compose обновляет Kotlin **копии** до 2.3.20. Это может изменить совместимость сцены относительно оригинала.

Нужен preflight проекта с понятным результатом и поддержка реально выбранного целевого проекта без изменения его основного checkout. Универсальная поддержка всех Gradle-схем не является условием первого пилота.

### 4. Импорт реальных экранов слишком узкий

`compose.mjs` принимает Text/Column/Row/Box/Card/Button/Spacer/Surface. Тело функции должно состоять из поддерживаемых вызовов; `if`, циклы, списки, собственные composable, большинство выражений и параметров требуют адаптеров. Button допускает один текстовый label; Box contentAlignment отклоняется. Ресурсные/параметрические тексты могут читаться, но изменение выражения передано на разрешение агенту.

`bindCapture` требует ровно один runtime-экземпляр на ключ вызова. Повторы одного call site не поддержаны. ID строится из структурного пути: его устойчивость при изменении дерева между импортами не гарантирована. Для повторного редактирования нужны устойчивые связи экземпляров и явная неоднозначность. Без адаптера нельзя незаметно подменять импорт ручным похожим макетом.

### 5. Свободное размещение ещё не проверено как поведение настоящего приложения

В free-режиме автоматический перенос превращает Row/Column в Box и фиксирует измеренную геометрию. Это обеспечивает размещение на исходном размере, но может потерять адаптивность. Требуется проверка другого viewport, font scale, длинного текста, RTL, insets и прокрутки. Агентская инструкция требует выбирать компоновку осмысленно; фиксированный конвертер не заменяет эту работу.

### 6. Повторный цикл работы не завершён как пользовательский сценарий

Нет управляемого завершения «агент перенёс → новый Android-кадр → проверено → актуальный baseline → следующая правка». Сейчас это совокупность команд и обязанностей агента. Защита устаревших исходников уже есть, но повторный импорт требует новой сессии/ручного выбора; автоматического согласования старого пользовательского черновика с новым исходником нет. Нужны однозначная связь снимка с результатом переноса и сохранение незавершённых правок.

В HTML-редакторе `localSave` хранит только текущий документ, а после reload создаётся новая History: Undo/Redo прежней сессии теряется. Нативный диагностический режим имеет другой контракт истории.

### 7. Конечный сценарий и создание экранов реализованы частично

Каталог Preview и CLI-список сохранённых сессий существуют. Переход по работающему приложению с включением редактирования текущего экрана — **B7 не реализован**. Запуск ограничен выбранным эмулятором; физические устройства не покрыты.

`generateCompose` создаёт Kotlin-экран, но обычный UI не предлагает создание отдельного пустого экрана, выбор экранов проекта и палитру его собственных компонентов. Добавлять элементы в текущую сцену уже можно. Навигация и поведение нового экрана должны оставаться работой агента, как согласовано с пользователем.

### 8. Установка и документация нуждаются в доводке

Setup проверяет наличие файлов и возвращает `ready:true` независимо от `native.buildReady`; недостаточная Android-среда отражается лишь вложенными флагами. Setup-skill всё ещё рекомендует цепочку native-run для «полного редактора», хотя основной skill правильно отличает PNG с рамками от редактора элементов. Документы содержат старые статусы «ещё не установлен» и предыдущие версии; планы не следует считать завершёнными по старым галочкам.

Обновления с разными исправлениями выпускаются под тем же 0.8.1. Для воспроизводимости нужны новая версия, changelog и проверка именно установленного пакета. Данные уже вынесены из пакета; следует проверить обновление/откат на копии существующей сессии. Работа Claude отложена и не нужна для первого выпуска Codex. Другие ОС не проверены.

## Что требуется до обычной работы, а что можно отложить

До рабочего пилота: исправить потерю свойств baseline, согласовать видимые возможности и перенос, подключить выбранный реальный проект, пройти два последовательных переноса и нативную проверку на двух сценах. Использовать отдельную копию; исходный проект менять только по поручению.

До заявленной законченной версии: закрыть B7, собственные компоненты/темы, создание/выбор экранов, понятное завершение переноса и воспроизводимое обновление. Это самостоятельные обязательства, а не мелкие косметические правки.

Можно отложить: другие UI-стеки, Claude, другие ОС, физический телефон при принятом сценарии эмулятора, мультивыбор, copy/paste и расширенную библиотеку шрифтов. Автоматический запуск агента по кнопке не является недостающей функцией: пользователь выбрал передачу намерения агенту.
