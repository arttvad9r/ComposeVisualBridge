# Экраны и установленный плагин — 12 октября 2026

Версия 0.9.0 реализует каталог сохранённых экранов/состояний, создание отдельного пустого экрана с необязательным запросом агенту и палитру компонентов проекта. Новый debug-адаптер работающего приложения компилируется в копии Subtrack. Шаги 5–6 плана готовности остаются открытыми до нативной приёмки переходов, темы и динамического списка; сборка и синтетические тесты протокола её не заменяют.

## Реализованный сценарий редактора

Управляемая сессия показывает сохранённые экраны того же проекта. Перед переходом браузер дожидается сохранения черновика. У каждого экрана сохраняются своя история, эталон и неизменяемый Apply. Новый экран резервирует отдельную сессию; `state.creationRequest` сохраняет пожелание пользователя. Генератор даёт Kotlin-представление поддерживаемого нового дерева, навигацию и поведение подключает агент после поручения.

Палитра содержит ревизию и source-связи собственных компонентов. Вставка создаёт независимые ID экземпляра, сохраняет связь в документе и помечается `requiresAgent`. Автоматический Kotlin-патч и генератор отклоняют новую вставку собственной палитры: шаблон отображения не подменяет исходный компонент.

Старые сессии без project-context и новых state-полей сохраняют обычный редактор. В автономном сервере каталог скрыт. Путь проекта берётся из контекста managed CLI; браузер передаёт ID сессии, не произвольный filesystem-путь. Устаревшая revision отклоняется до перехода. Ошибка каталога не выключает редактор текущего черновика.

## Debug-адаптер текущей сцены

`prepare-live` создаёт копию с исходными Kotlin/KSP и без Buddy Preview; `live-run` запускает обычную Activity. Кнопка внутри debug-копии захватывает текущий экран после обычной навигации. `edit-live` сверяет восстановленную копию, локальный и установленный APK, время запуска и captureId. Разные захваты создают разные сессии; повторный captureId возвращает прежнюю с её черновиком.

Связи имеют явные ключи вызовов и стабильные идентификаторы данных; повторная идентичность блокирует импорт. Синтетический тест с fake adb проверяет два разных корня, перестановку одинаковых строк, разные экземпляры, stale-исходник/APK/кадр и отказ при повторном ключе. Этот тест не подключается к Android.

Настоящая сборка Subtrack прошла в `/tmp/cvb-subtrack-live-final-20261012`: `:app:assembleDebug`, Kotlin 2.1.0, KSP 2.1.0-1.0.29, исходный Compose BOM 2024.12.01 и Room 2.6.1. Debug applicationId — `com.arttvad9r.subtrack.composebridge`, подпись создана только внутри копии. SHA прочитанных исходников совпали с адаптером; host и все инструментированные экраны восстановлены побайтно. Основной Subtrack не изменялся. Evidence: `/tmp/cvb-subtrack-live-build-evidence-20261012.json`.

Эмулятор не загрузился: запуск собственной аренды через `android-emu claim oneplus-13s-1` сообщил `/dev/kvm is not found`. Поэтому установка этого APK, настоящие переходы/захваты, смена темы и динамический список на втором проекте **не приняты**. Рабочий пилот Mealio остаётся отдельно принятой проверкой предыдущего этапа.

## Установленный пакет

Штатные `codex plugin marketplace add` и `codex plugin add` установили 0.9.0 в отдельный `/tmp/cvb-plugin-install-home-20261012`; installed/enabled подтверждены CLI. Новый процесс app-server создал новую ephemeral-сессию и обнаружил оба skills из установленного cache; `plugin/read` разрешил onboarding. Model turn и автоматический выбор skill моделью в этом тесте не выполнялись. Пользовательский профиль Codex не менялся. Механизм локального marketplace описан в [официальной документации OpenAI](https://developers.openai.com/plugins/build/plugins).

Автоматизированный браузерный сценарий из установленного cache проверил два экрана, палитру, Apply/read, поздний черновик, переход туда и обратно, stop/open, восстановленную историю и новый экран с запросом. Затем штатный CLI Codex выполнил 0.9.0 → 0.8.4 → 0.9.0 на копии данных: байты session.json, handoff, поздний черновик и Undo-история сохранились. Серверы этих проверок остановлены. Evidence: `/tmp/cvb-plugin-new-conversation-evidence-20261012.json`, `/tmp/cvb-plugin-upgrade-evidence-20261012.json`.

Setup и основной skill используют edit-compose как путь редактирования существующего экрана, edit-scene — для подготовленной runtime-сцены. Сообщение setup разделяет комплект редактора, найденный Android toolchain и экспериментальный live-захват. Эскиз с ручным JSON требует явного согласования. Установка кнопкой и автоматическое onboarding в интерфейсе приложения остаются отдельной непроверенной частью.
