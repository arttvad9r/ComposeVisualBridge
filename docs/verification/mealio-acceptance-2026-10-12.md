## Два переноса

1. В Chromium выбран экземпляр DARK, его фон изменён на `#FFF2CC`, сохранён тестовый снимок. Перед переносом проверен sourceHash. В существующий FilterChip добавлено условие цветов только для DARK. После сборки получены настоящий кадр и новый baseline: фон совпал, стабильный ID сохранился, все остальные чипы попиксельно неизменны.
2. На новом baseline экземпляр DARK удалён через интерфейс, сохранён следующий снимок. В Kotlin изменён существующий цикл ThemeMode, исключающий DARK. После сборки и нового захвата чипов стало пять вместо шести, остальные ID сохранились и соседи попиксельно неизменны.

Повторное чтение обоих handoff вернуло тот же снимок после подготовки результата. В каждой итерации прошёл настоящий instrumentation-тест: выбор доступных тем и языка вызывает исходные callbacks; отключение открывает диалог, отмена не вызывает отключение, подтверждение вызывает его один раз и закрывает диалог. Подписи получены через настоящие Android string resources. Проверяется поведение SettingsScreen с тестовым состоянием; сетевые операции и навигация приложения не входят в этот тест.

## Исправления редактора

- Координаты free-детей учитывают внутренний край CSS-рамки без смещения относительно Compose.
- Runtime-захват сохраняет реальную шкалу sp→dp, размер шрифта TextLayoutResult, разрешённый letterSpacing, границы/ширины строк, межстрочный шаг и многоточие. Измеренная одна строка сохраняет исходный maxLines=2. Существующий onTextLayout вызывается после сохранения измерений.
- Неизменённые строки используют нативные переносы и ширины после загрузки локального шрифта. После изменения текста, типографики, ширины или fontScale старые метрики не подменяют новое CSS-размещение. Для окончательной сверки правки нужен новый Android-захват.
- Для Button отдельно сохранены ширина подписи и видимая область заливки внутри области нажатия. Центрируется весь текстовый блок; строки внутри него имеют своё выравнивание. Убрана повторная компенсация leading у многострочной кнопки.
- Системный Roboto определяется по SHA-256 файла, выбранного TextRunShaper для Typeface.DEFAULT. Для проверенного API 37 добавлен неизменённый Roboto 3.015 с OFL, прежний Roboto 3.005 сохранён. Неизвестный хеш требует сверки эталона. [Официальный выпуск шрифта](https://github.com/googlefonts/roboto-3-classic/releases/tag/v3.015), [лицензия](https://github.com/googlefonts/roboto-3-classic/blob/main/OFL.txt).

Измерения описаны в [протоколе](../protocol.md), правила переноса — в [AGENT.md](../../AGENT.md). Схема остаётся version 1; старые сессии читаются. Новые измерения требуют отдельного свежего импорта.

## Проверки

Устройство: пользовательский тестовый OnePlus 13s, `emulator-5584`, API 37. Рабочая плотность проверки — 320 dpi. Для каждого состояния выполнены `:app:assembleDebug`, проверка каталога APK/sourceRevision, запуск настоящего Preview и новый захват. Копия использует Buddy 0.3.0, Kotlin 2.3.20, KSP 2.3.6 и JDK 21. Только в копии тестовые AndroidX зависимости обновлены до junit 1.3.0, runner 1.7.0, core 1.7.0 и Espresso 3.7.0 для проверки на API 37.

Геометрия каждого узла сверена с нативными bounds, допуск менее 0.6 dp. Проверено число видимых строк и многоточие, верх/низ строк с допуском 2 dp, горизонтальные границы текста — 3 dp, RGB заливок и отступов — 4 единицы канала. Результат не означает одинаковую растеризацию Android и Chromium. Маленькая общая ошибка фоновых пикселей не используется как критерий приёмки.

При 160% исходный Mealio переносит подписи «Светлая» и «Русский» на две строки, а English полностью отсекается узким Row. Редактор воспроизводит это состояние; проверка скрытой подписи включена в число текстовых областей обоих больших шрифтов. Адаптивность самого Mealio не исправлялась. Высокий viewport дополнительно проверяет весь оставшийся текст нижней карточки.

Итог: **71/71 Node**, **55/55 Chromium**, обе нативные проверки callbacks, семь захватов и сравнения по элементам прошли. `node --check` изменённых модулей прошёл. `npm test` также пересобрал переносимый пакет 0.8.3 и проверил его через plugin-тесты.
