# Архитектура и разработка

## Устройство

```text
Исходники UI → агент → JSON-макет → локальный редактор
                                      ↓ Apply
                         baseline + proposed + changes
                                      ↓ поручение
                         агент → правки кода → проверка
```

`server.mjs` обслуживает статические файлы и API, валидирует запись, сериализует операции внутри процесса и сохраняет session.json заменой временного файла. Apply создаёт отдельный каталог со снимком.

Состояние в памяти обновляется только после успешной записи session.json. При обрабатываемой ошибке сервер удаляет временный файл и каталог неудачного Apply; прежняя ревизия и успешный снимок остаются доступны. Ошибка хранилища возвращает HTTP 500, ошибка входных данных — 400. Если удалить незавершённую запись тоже не удалось, причина выводится в терминал. При аварийном завершении процесса очистка не гарантируется. GET handoff фиксирует указатель снимка перед чтением файлов, чтобы параллельный Apply или импорт не смешивал документ и метаданные разных снимков.

HTTP-тело собирается из Buffer с лимитом по байтам и декодируется в UTF-8 один раз: границы сетевых частей не повреждают русский текст и emoji. Перед импортом браузер сохраняет актуальный черновик и блокирует ввод до завершения операции. Ошибка записи или конфликт останавливает импорт; локальная правка остаётся доступной для экспорта. Успешный импорт архивирует уже сохранённый черновик.

`storage.mjs` записывает инструментирование Kotlin и восстановление через временный файл и атомарную замену в том же каталоге. Вспомогательный файл создаётся исключительно, без замены существующего файла. Манифест с оригиналами сохраняется до изменения исходников; при неудачном rollback сцены он остаётся для повторного восстановления. Аварийное завершение может оставить часть файлов инструментированными и временные файлы; восстановление принимает как оригинальные, так и полностью инструментированные файлы, но отклоняет посторонние изменения. Это защита от частичной записи и прерывания процесса, а не гарантия сохранности при отказе оборудования.

`public/model.mjs` — общая модель для браузера и сервера: валидация, индексация дерева, diff, структурное перемещение и история. `public/app.mjs` — выбор, свойства, рендер, drag/resize и очередь сохранения. `public/style.css` — адаптивный интерфейс; `public/index.html` — оболочка. `tests.mjs` проверяет модель и API; серверные тесты создают временный каталог и свободный порт. `examples/server-screen.json` — независимое демо с фиктивными source-ссылками.

baseline — отправная точка; current — черновик; applied — указатель последнего явного снимка. revision — версия серверной сессии, sourceRevision — снимок исходного проекта. Это разные значения.

## Работа с кодом

1. Прочитайте спецификацию и текущий план. Для небольшой правки отдельный план не нужен.
2. Запустите отдельный dev-сервер: `PORT=4180 BRIDGE_DATA=./data/dev npm start`. Не используйте чужую открытую сессию для разрушительных проверок.
3. Меняйте модель и renderer согласованно; новые свойства должны иметь валидацию, diff и документированное отображение в целевой стек.
4. Запустите `npm test` и `node --check` для изменённых JavaScript-модулей.
5. Для UI запустите `npm run test:browser` и проверьте затронутый пользовательский сценарий. Node-тесты не доказывают работу drag в браузере.

Для отдельной проверки Kotlin-размеров и отступов используется `tests/android/geometry.mjs` с подготовленной минимальной Android-копией и новым каталогом результатов. Стенд создаёт собственный AVD, редактирует поля через Playwright, сохраняет тестовые снимки и проверяет настоящий Android после двух переносов. Требования, команда и обнаруженные расхождения — в [отчёте](verification/android-geometry-2026-10-11.md). Он не входит в обычный npm test; его нативные assertions и `visualMatches` оцениваются отдельно.

Изменения frontend видны после перезагрузки страницы. После изменения импортируемого сервером model.mjs перезапустите Node: модуль в процессе кэшируется. Черновик сохраняется, история Undo при перезагрузке теряется.

## Хранение и ограничения

Для воспроизводимой ручной проверки редактора запускайте `npm run browser:scenarios`: отдельный временный BRIDGE_DATA, свободный порт и макет с вложенными/перекрывающимися элементами. Ctrl+C удаляет данные стенда. [Сценарии и критерии проверки](verification/browser-scenarios.md).

Автоматические проверки: после `npm ci` один раз выполнить `npx playwright install chromium`, затем `npm run test:browser`. Playwright — dev-зависимость; каждый тест запускает отдельный сервер на свободном порту с временными данными и очищает их после завершения. Проверки находятся в `tests/browser/editor.spec.mjs`, конфигурация — `playwright.config.mjs`. При сбое снимок экрана, контекст и trace сохраняются в игнорируемом `test-results/`; открыть trace можно командой `npx playwright show-trace <путь-к-trace.zip>`. Локально и в CI нужны системные библиотеки Chromium; при их отсутствии следовать сообщению Playwright. Другие браузеры пока не проверены.

`data/` игнорируется Git. Вариант с BRIDGE_DATA вне data нужно также исключить из Git или хранить вне репозитория. Сессии могут содержать пользовательский текст и пути; не включайте их в коммиты.

HTTP доступен на loopback. Проверяются Host и Origin, размер JSON до 2 MB, Content-Type и revision. Это не система удалённого доступа: аутентификации, многопользовательского режима и блокировки каталога между процессами нет. Имея локальный доступ, другой процесс может обращаться к API.

Для обычного JSON-макета ссылки и sourceRevision создаёт агент. Compose-адаптер импортирует поддерживаемый синтаксис, проверяет хеши и ревизию рабочей копии; runtime-сцены требуют привязок агента. Эти адаптеры не являются универсальным Kotlin-парсером. Лицензия распространения пока не выбрана; не добавляйте её от имени владельца.

## Сборка плагина

`npm run package:plugin` создаёт готовый runtime-пакет, локальный marketplace и tgz в dist/. Источники manifest и skills — plugin/, управление сессиями — scripts/plugin.mjs. dist/ игнорируется Git; пользовательские данные выбираются вне установки по docs/plugin.md. `npm test` предварительно собирает пакет и проверяет его после распаковки и переноса. Интерактивную установку и onboarding проверять отдельно; native plugin/read/list подтверждают доступность пакета, но не его установку.

## Проверка исходника и пакет v0.3.0

baseline.mjs формирует fingerprint, метаданные эталона и подтверждение с bridgeVersion. Сервер проверяет review до создания каталога снимка. public/baseline-ui.mjs открывает сравнение и подтверждение; изображение хранится отдельно от GET session и копируется в reference.json снимка. Импорт сохраняет старую сессию в session-N-ID/session.json; restore архивирует заменяемую сессию. Прямой сервер держит .bridge-server.lock и удаляет его при нормальном выходе. Низкоуровневый open удаляет lock только мёртвого сервера, под своим .bridge-open.lock. Managed open перезапускает сервер другой версии, сохраняя данные.

Типографика в sp учитывает viewport.fontScale только при отображении. Локальные шрифты поставляются с лицензиями; CSS, шрифты, baseline.mjs и оба протокола входят в переносимый пакет. schemaVersion=1 сохранён, новые поля совместимы со старыми документами. Изменения layout.frames вынесены в intent.technical и не увеличивают пользовательский счётчик правок.

Проверки: 21 Node и 34 Chromium. Помимо исходной рабочей копии проверена чистая временная копия текущих исходников через npm ci → npm test → npm run test:browser и node --check всех модулей. Native Codex install/discovery/setup проверены в отдельном CODEX_HOME без изменения пользовательского профиля.

## Native Preview

Оригинальный Compose UI подключается через native.mjs (Node.js 22+ для WebSocket), public/native.* и scripts/native.mjs. Legacy-модель и native-session.json независимы. Проверяйте опубликованный wire-протокол Buddy (`cmd` для команд, `type` для ответов), неизменность исходного кадра при черновике и сохранённых передач. Инструкция: [native-ui.md](native-ui.md); реальная Android-проверка и ограничения: [отчёт](verification/native-preview-2026-10-11.md). Только отдельные BRIDGE_DATA/Android-копия/AVD, без подмены пользовательской сессии.

Подготовка и compiler discovery: scripts/native-project.mjs, команды prepare/build/catalog; plugin.mjs предоставляет prepare-native/native-build/native-catalog. Поддержка ограничена обычным Android application-модулем с Kotlin DSL. Копия создаётся только в новом каталоге вне исходного Git-root; никакого редактирования проекта на месте. Buddy KSP 0.3.0 требует JDK 21, Gradle KSP 2.3.6. Catalog связан с source/APK SHA и не создаётся при ошибке Gradle, отклоняется после изменения входов. Реальная проверка: [отчёт discovery](verification/preview-discovery-2026-10-11.md).

`source-map.mjs` строит лексический индекс Kotlin и простых строковых ресурсов из проверенного каталога сборки, без сторонних runtime-зависимостей. Он возвращает кандидатов, а не Kotlin AST или точный source map. Native API проверяет ревизию исходников и APK при подключении, записи намерений и Apply. Проверки: `tests/source-map.test.mjs` и сценарий N03 в `tests/browser/native.spec.mjs`.

## Полный native-редактор

Общая оболочка — public/index.html, dispatch — public/entry.mjs, провайдеры — app.mjs и native.mjs. /app.mjs отдаёт собранный entry.js; /native использует ту же HTML-оболочку. Native controller отвечает за измеренные координаты, инспектор, намерения, структуру, жесты и очередь сохранения. native.mjs на сервере проверяет свойства/историю/передачу; source-map.mjs разрешает только Preview проверенной сборки. scripts/native-device.mjs управляет выбранным тестовым эмулятором, APK, Activity и принадлежащим сессии ADB forward.

Проверки: tests/native-editor.test.mjs (свойства, структура, история, захват, настоящее сравнение), tests/native-device.test.mjs (CLI, адрес/serial, установка и cleanup), tests/browser/native.spec.mjs (полные панели, жесты, быстрые сохранения, конфликт и восстановление). Реальный Android-цикл описан в verification/full-native-editor-2026-10-11.md.
