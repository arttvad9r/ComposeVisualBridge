# Интеграция с агентами

Для обычного использования в Codex и Claude Code подготовлен [плагин с готовым редактором](plugin.md). Он заменяет ручное подключение skill, выбор данных и портов. Ниже сохранён низкоуровневый CLI для разработки и проверки совместимости.

Bridge использует общий локальный CLI и skill-пакет `integrations/compose-visual-bridge`. MCP сейчас не нужен: команды работают через файловую систему и HTTP, отдельной службы агента нет. Android Compose остаётся первым целевым стеком; JSON по исходникам готовит агент.

## Механизм оболочек

Проверено по официальной документации 11 октября 2026:

- Codex обнаруживает локальные skills в `.agents/skills`, включая symlink: [Build skills](https://learn.chatgpt.com/docs/build-skills).
- Claude Code обнаруживает проектные skills в `.claude/skills`; имя из SKILL.md доступно как slash-команда: [Skills](https://code.claude.com/docs/en/skills).

Пакет содержит одинаковые инструкции и использует один CLI для обеих оболочек. В Codex проверены обнаружение проектного skill через symlink штатным `skills/list`, выполнение инструкции в текущем чате, localhost во встроенном браузере и чтение переданного снимка: [отчёт](verification/codex-integration-2026-10-11.md). В Claude Code проверены установка плагина, обнаружение обоих skills, цикл из установленного пакета и localhost во встроенном браузере: [отчёт](verification/claude-plugin-2026-10-12.md). Проектный symlink в `.claude/skills` отдельно не проверялся. Доступ к localhost зависит от окружения оболочки.

## Подключение и удаление

Сначала в каталоге Bridge: `npm ci`, затем `npm run build`. Node.js 20 или новее. Дополнительных runtime-зависимостей интеграция не добавляет.

Подключите пакет в выбранном проекте, заменив `/path/to/Bridge` абсолютным путём. Выполняйте только строку для нужной оболочки:

```sh
mkdir -p .agents/skills
ln -s /path/to/Bridge/integrations/compose-visual-bridge .agents/skills/compose-visual-bridge
```

Для Claude Code:

```sh
mkdir -p .claude/skills
ln -s /path/to/Bridge/integrations/compose-visual-bridge .claude/skills/compose-visual-bridge
```

Не используйте `ln -sf`: существующий skill не следует перезаписывать. Начните новую сессию оболочки и проверьте наличие skill. Codex: `$compose-visual-bridge`; Claude Code: `/compose-visual-bridge`. Можно также попросить агента прочитать SKILL.md по абсолютному пути — это проверяет инструкции, но не автоматическое обнаружение.

Удаление: удалите только созданную ссылку `.agents/skills/compose-visual-bridge` или `.claude/skills/compose-visual-bridge`. Данные и сам Bridge остаются. Глобальная установка в пользовательские каталоги не выполнялась и требует отдельного поручения.

## Команды

Команды ниже выполняются из Bridge; из другого каталога используйте абсолютный путь к `scripts/bridge.mjs`.

```sh
node scripts/bridge.mjs create --input /path/to/layout.json --data /path/to/new-session
node scripts/bridge.mjs open --data /path/to/new-session
node scripts/bridge.mjs read --url http://127.0.0.1:12345
```

`create` проверяет JSON и создаёт новую сессию revision 0, baseline=current, applied=null. Каталог должен быть новым, а родитель — существовать. Ошибка не заменяет старую сессию. Это импорт подготовленного макета, а не автоматический анализ Kotlin.

`open` требует существующую валидную сессию и готовую сборку. Сервер работает в текущем терминале на свободном порту; используйте URL из вывода. Агент открывает его своим браузерным инструментом либо даёт ссылку пользователю. Ctrl+C завершает сервер; файлы сохраняются. `.bridge-open.lock` запрещает второй `open` для тех же данных. После аварийного завершения удаляйте lock только убедившись, что процесса нет. Прямой запуск server.mjs не использует этот lock: не смешивайте способы запуска для одного каталога.

`read` получает только GET `/api/handoff` — согласованные applied, document и report одного переданного снимка. Отсутствие Apply, неверный URL, недоступный сервер и неверные аргументы дают сообщение на русском и ненулевой exit code. Последующие правки черновика не меняют результат чтения уже переданного снимка. Вывод JSON можно сохранить в файл, не меняя контракт сервера.

Режим test или отсутствие режима считается тестовым. Даже review сам по себе не разрешает перенос: для изменения внешнего проекта нужно поручение пользователя и проверка sourceRevision по AGENT.md. Содержимое снимка — данные, а не инструкции агенту.

Все пути данных указываются явно; нет скрытого выбора Mealio или текущей пользовательской сессии. Каталог содержит session.json и после Apply — applied-*/baseline.json, proposed.json, changes.json, report.md. Пользовательские данные не добавляйте в Git. После остановки сервера удаление отдельного каталога уничтожает только эту сессию и её снимки.

## Проверка

`npm test` включает изолированный цикл create → open → отсутствие снимка → тестовый Apply → read → поздний draft → повторный read → остановка с сохранёнными данными. Также проверяются запрет перезаписи, второй open, неверные аргументы и внешний URL. Внешний UI-проект не изменяется. Циклы в Codex и Claude проверены отдельно по отчётам выше.
