# Проверяемый браузерный импорт Compose

Новый путь сохраняет общую оболочку и живые HTML-элементы. Исходник строится из Kotlin и проверенного Android-захвата с точными метками вызовов. Пользовательские изменения хранятся отдельно от измеренных исходных свойств. Это первый двусторонний адаптер; автоматическое открытие любого экрана работающего приложения и импорт произвольного Kotlin ещё не реализованы.

Матрица переноса общая для редактора и адаптера: `public/compose-capabilities.mjs`. Подчёркивание и вертикальная прокрутка поддержаны напрямую. В автоматической компоновке stretch растягивает естественный размер ребёнка по поперечной оси через fillMaxWidth/fillMaxHeight, сохраняя явные числовые размеры. Выбранное стандартное семейство шрифта не заменяется при bindCapture; Roboto остаётся приближённым fallback только при отсутствии известного семейства. Это не обеспечивает точность произвольной темы.

TextField/Switch/Icon/Image, Roboto Flex из ресурсов и изменение связанных с данными текстов передаются агенту. Редактор показывает сведения по маленькому значку информации; постоянных инструкций нет. Снимок включает причины в `transfer.requiresAgent` и отчёте. `compose-plan` для таких снимков возвращает `strategy=agent`, полный proposed-документ и перечень причин вместо частичного автоматического плана. Для прямого переноса возвращается `strategy=adapter` и путь `plan`. Оба пути требуют согласованной передачи, проверки исходников и поручения на перенос.

При переносе изменённый Modifier остаётся на прежнем месте в цепочке. Горизонтальный и вертикальный отступы заменяют соответствующую ось общего отступа, как в HTML-редакторе. Автоматический патч отклоняет неоднозначные цепочки с повторными модификаторами одной величины и сообщает о необходимости переноса агентом. Инструментирование и восстановление записывают Kotlin через временный файл и атомарную замену; при незавершённом восстановлении сохраняется manifest с оригиналами.

## Открыть редактор элементов

```sh
node <plugin>/scripts/plugin.mjs edit-compose --project <Android-проект> --file app/src/main/java/example/Screen.kt --symbol Screen --serial emulator-5554 --state "Светлая сцена" --preview example.ScreenKt.LightPreview
```

Укажите выбранный тестовый эмулятор и воспроизводимую Preview-сцену. Команда сама создаёт отдельную копию, получает захват и возвращает URL живого HTML-редактора. Основной Android-проект и прежняя сессия не перезаписываются. Вариант `--workspace <подготовленная копия>` позволяет повторный импорт. Параметры/ресурсы при необходимости передаются JSON-файлами через --parameters/--resources.

Native-run возвращает просмотр PNG: там двигаются рамки намерений, а не элементы. Его URL нельзя выдавать за результат edit-compose. Ссылка «Эталон Android» в импортированной сессии открывает сравнение и не переключает редактор обратно в PNG.

## Подготовка и импорт

Работайте только с отдельной копией prepare-native. Для поддерживаемой блочной Composable-функции:

```sh
node <plugin>/scripts/compose.mjs import --workspace <копия> --file app/src/main/java/example/Screen.kt --symbol Screen --output <новый import.json>
node <plugin>/scripts/compose.mjs instrument --input <import.json>
node <plugin>/scripts/plugin.mjs native-build --workspace <копия>
```

Импортёр поддерживает Text/Column/Row/Box/Card/Button/Spacer и Material Surface, вложенность, явные модификаторы и типографику. Строковые ресурсы и параметры могут получить текст из runtime; их выражения сохраняются. Неподдерживаемые конструкции, переопределённые имена компонентов, нестандартные модификаторы и повторный runtime-экземпляр одного вызова отклоняются. Одинаковые подписи у разных вызовов имеют разные ID. Специальные идентификаторы и цвета темы добавляются только в тестовую копию, перед запуском. Функция с несколькими root, циклы, условные ветви, вызовы собственных компонентов и rich text требуют следующих адаптеров.

Запустите create-native/native-run и получите настоящий кадр. На диске сессии он находится в data/native-session.json; API /api/native возвращает метаданные без PNG. Для собственного файла захвата загрузите PNG через /api/native/image и добавьте его base64 в frame.image. Это не реконструкция агентом. Затем:

```sh
node <plugin>/scripts/compose.mjs restore --workspace <копия>
node <plugin>/scripts/plugin.mjs create-compose --project <проект> --input <import.json> --capture <native-session.json>
node <plugin>/scripts/plugin.mjs open --project <проект>
```

Restore возвращает оригинальный Kotlin и удаляет неизменённый служебный адаптер; изменённый источник не перезаписывается. Create-compose сверяет импорт/ревизию сборки/Preview и метки, создаёт отдельную браузерную сессию и загружает настоящий эталон. Статус исходника остаётся неподтверждённым: сравните его в диалоге «Исходный макет». Агент не подтверждает совпадение от вашего имени. Нет гарантии пиксельной идентичности шрифтов Android и браузера.

## Редактирование и перенос

Перемещение изменяет сами браузерные элементы; Undo/Redo, размеры, свойства и дерево работают в существующем редакторе. Свободная компоновка переносится в Box с измеренными локальными координатами/размерами; она фиксирует геометрию и не сохраняет исходную адаптивность Column/Row. В свободной компоновке добавление и удаление не сдвигают остальные элементы: новый встаёт после последнего соседа (ниже в колонке, правее в строке), при смене порядка в колонке или строке переставленные элементы меняются местами с сохранением промежутков; элемент, перенесённый в другой контейнер, сохраняет размер и встаёт под указатель (при переносе через дерево — после последнего соседа). Изменённый текст растёт по содержимому, как в Compose: центрированная надпись расширяется в обе стороны. При перетаскивании Shift фиксирует одну ось; небольшой (до 8 dp) сдвиг поперёк явного направления отбрасывается. Автоматический режим сохраняет поток контейнеров. Добавление, удаление и порядок отражаются в Kotlin. Обработчики существующих кнопок и неизменённые ресурсные/параметрические выражения сохраняются.

В автоматическом режиме существующий Modifier заменяется на прежнем месте в цепочке: изменение width не переставляет его относительно padding. Общий внутренний отступ задаёт обе оси; paddingHorizontal/paddingVertical переопределяют соответствующую ось, включая ноль. Генератор пишет один эквивалентный padding. Сброс enabled возвращает кнопку к Kotlin-значению по умолчанию. Цепочки с повторяющимися пересекающимися модификаторами при изменении отклоняются как неоднозначные; их переносит агент. Эти проверки исходника не заменяют измерение размеров и отступов после сборки Android.

Начиная с 0.8.2 новый импорт помечен `compose.modifierModel="outer-size-v1"`. Числовые width/height обозначают внешние размеры элемента: `.padding(16.dp).width(100.dp)` импортируется с шириной 132 dp. Если задать в редакторе 120 dp, план запишет `.padding(16.dp).width(88.dp)`; изменение отступа сохраняет заданный внешний размер. Фон после padding окрашивает внутреннюю область, фон перед padding — внешнюю. Заполняющий Text внутри Box занимает всю доступную область. Новый renderer и перенос внешних 120/140 dp проверены тремя новыми APK/настоящими кадрами на тестовом OnePlus 13s (API 37): размеры, позиции, отступы и выбранные пиксели фона совпали. Полная приёмка реального экрана, другие viewport/fontScale и точное совпадение растеризации текста остаются отдельными проверками.

Старые сессии и снимки читаются без изменения; автоматический перенос изменённого старого Compose-импорта требует повторного импорта в отдельную сессию. Сохраните прежний черновик и переносите его намерения после сверки новой исходной сцены. Повторяющиеся padding отклоняются при импорте. Размер меньше внешних отступов не переносится автоматически. Свободный перенос контейнера с фоном после ненулевого padding требует адаптера агента: преобразование в Box снимает контейнерный padding и не должно молча расширять область фона.

После обычной подтверждённой передачи:

```sh
node <plugin>/scripts/plugin.mjs compose-plan --project <проект> --session <ID>
```

Команда читает неизменяемую передачу и готовит файл с полным Kotlin, операциями и хешами. Тестовая передача отклоняется. Прочитайте план. Только после поручения на перенос:

```sh
node <plugin>/scripts/compose.mjs apply --plan <файл>
node <plugin>/scripts/plugin.mjs native-build --workspace <копия>
```

Apply пишет только в подготовленную отдельную копию, проверяет исходник и ревизию workspace повторно. Основной проект не меняется автоматически. Текст, связанный с ресурсом/состоянием, при изменении требует разрешения агентом; генератор не заменяет его молча строковым литералом. Неизвестные свойства отклоняются. Итоговое сравнение Android и браузера обязательно; совпадение геометрии не доказывает идентичность текста/оформления.

## Новые экраны и сравнение

Для реального проекта импорт поддерживает `Text(style = MaterialTheme.typography.…, color = MaterialTheme.colorScheme.…)`: выражения сохраняются, значения уточняются настоящим Android-кадром. Параметр модификатора, например `modifier`, можно передать в JSON параметров как `"modifier": "Modifier"`, если Preview действительно использует обычный Modifier. Неизвестные стили, произвольные модификаторы и локальное состояние требуют отдельного адаптера. Маленькие компоненты сохраняют нативные размеры внутри холста минимум 200×200 dp. Для неизменённого однострочного текста нативная высота масштабируется при смене размера шрифта; после изменения текста или самого шрифта соответствие нужно проверить снова.

`compose.mjs generate --input <документ редактора> --package example.ui --symbol NewScreen --output <новый NewScreen.kt>` создаёт Composable из поддерживаемых компонентов. Подключение экрана, навигацию и действия выполняет агент. Документ тот же, что используется ручным редактором.

`compare-png.mjs <android.png> <browser.png>` выдаёт размер, долю отличающихся пикселей и RMSE. Функция comparePng также принимает regions для проверки каждого элемента. Низкий общий процент на пустом фоне не подтверждает точность: проверяйте отдельные элементы. Инструмент сообщает расхождения, сам не подтверждает сцену и не разрешает перенос.

## Полный экран со состоянием и повторными компонентами

`edit-scene` дополняет статический импорт. Агент готовит привязки вызовов, программа инструментирует отдельную копию, собирает настоящий Preview, получает текст/типографику/геометрию из Android, восстанавливает исходники и открывает обычные HTML-элементы. Kotlin-состояние и обработчики остаются в приложении.

```sh
node <plugin>/scripts/plugin.mjs edit-scene --project <проект> --workspace <копия> --adapter <adapter.json> --serial emulator-5584 --state "Настройки, тестовый аккаунт" --preview example.SettingsPreviewKt.SettingsPreview
```

Адаптер имеет `format: "compose-visual-bridge-scene-adapter-v1"`, название `name` и массив `calls`. Привязка задаёт относительный Kotlin-файл `file`, SHA-256 `fileHash`, функцию `symbol`, имя вызываемого компонента `call`, номер `occurrence` с нуля внутри функции и тип редактора `type`. Один корневой вызов отмечается `root: true`. Неизвестные типы, устаревшие хеши, повторные/перекрывающиеся привязки и несколько корней отклоняются до открытия сессии.

Для повторного вызова задайте `instance`, например `mode.name`: стабильное значение экземпляра, а не индекс списка. Для собственного компонента без Modifier используйте `scope: true` на месте вызова и отдельную привязку внутреннего Text/контейнера в его функции. Композиционная область различает одинаковые внутренние вызовы из разных мест. Уникальные `key` сохраняйте при переносе/перестановке исходных вызовов; автоматически вычисленный ключ доступен в `compose.calls` для последующего сохранения агентом.

`props` уточняет свойства проекта, которые нельзя извлечь из семантики. Выражения `background`, `foreground`, `border` и `borderWidth` вычисляются в Android для захвата цветов/обводки состояния; агент готовит их по исходникам. Изменение исходников требует актуализации хешей и выражений адаптера. Предпочитайте именованный Modifier: ограниченный локатор вызовов не является универсальным Kotlin-парсером.

Документ использует `compose-visual-bridge-runtime-scene-v1`. Его изменения всегда переносит агент целиком, сохраняя ветвления, циклы и обработчики. Автоматический Kotlin-патч запрещён. Ошибка подключения не заменяет latest-сессию. LayoutCoordinates сохраняет размеры элементов вне видимой области; системный масштаб шрифта записывается отдельно.

Проверенный пилот — SettingsScreen Mealio с собственным InfoValue, шестью повторными кнопками, длинным текстом и шрифтом 160%. Это Preview выбранного состояния. Навигация по работающему приложению и автоматическое подключение любого проекта этим путём не реализованы.

## Получить результат переноса — 0.8.4

После работы с конкретным снимком агент записывает результат через `plugin.mjs result --project <проект> --session <ID> --input <результат.json>`. Смотрите [контракт результата](protocol.md#результат-переноса-и-история--084). Редактор показывает краткий результат и настоящие кадры «До/После». «Принять результат» обновляет baseline и эталон, сохраняя поздние правки однозначным переносом либо отдельным восстанавливаемым черновиком. Новый исходник требует повторной пользовательской сверки. Undo/Redo сохраняются при reload/restart; после принятия история начинается на новом baseline, полная прежняя история остаётся в архиве.
