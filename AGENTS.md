# Правила разработки Compose Visual Bridge

- Пользовательский интерфейс и документация — на русском. Английский допустим для технических имён, терминов и API.
- Назначение проекта: браузерный редактор и протокол передачи визуальных правок агенту. Первый целевой стек — Android Compose; не считать универсальную генерацию кода уже реализованной.
- Перед существенной работой читать docs/specs/project.md и docs/plans/development.md. План отмечать только после проверки; завершённый план удалить после переноса актуальных сведений в постоянную документацию.
- Не применять сохранённые правки к внешнему UI-проекту без поручения на перенос. Apply готовит снимок и сам не запускает агента. Существующая сессия Mealio тестовая.
- Не перезаписывать пользовательскую сессию ради проверки. Использовать отдельный BRIDGE_DATA и свободный PORT. Не запускать два процесса с одним каталогом данных.
- Сервер работает без внешних runtime-зависимостей; браузер использует @dnd-kit/dom, сборка и стенд — esbuild и Pragmatic как dev-зависимости. Новые зависимости добавлять, когда они решают конкретную задачу; не менять стек без необходимости.
- Согласовывать новые свойства с валидатором, renderer, протоколом и инструкцией агенту. Сохранять совместимость или описать миграцию.
- Проверки: npm test; node --check для изменённых модулей. Для UI сначала использовать автоматизированный браузерный тест, если он покрывает затронутый сценарий. Интерактивный Browser Use нужен только для непокрытого поведения или когда существенна визуальная проверка; Node-тесты сами по себе не подтверждают перетаскивание.
- data/, пользовательские снимки, временные файлы и секреты не коммитить. AGENT.md описывает использование продукта агентом; этот файл — разработку самого продукта.
